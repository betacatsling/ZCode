# Trusted Harness assets (P0–P6 component)

Owner: the Node asset registry owns the fixed ID → packaged PNG byte mapping. Manifests carry opaque `iconAssetIdSchema` IDs only; registry metadata does **not** register executable adapters or declare availability. The renderer owns only image load/failure presentation, never reads a file, opens a backend URL, or fetches an arbitrary manifest URL.

Contract: `resolveHarnessAsset(id)` asynchronously returns `{ kind: "trusted-png", mimeType: "image/png", base64 }` or undefined. Only statically registered IDs are readable. PNG bytes are bounded to 256 KiB, width/height 1–1024, exact MIME/signature/chunk boundaries, no trailing data; SVG, remote URLs, paths, markup and arbitrary descriptors are rejected. Transport/mount must pass this exact descriptor, not a URL or filesystem path. UI checks the descriptor shape, size, signature and dimensions again before constructing a PNG data URL. Data URLs can only be constructed from this typed validated raster; no HTTP request, custom scheme or renderer IO. Image load failure and unknown IDs show a neutral initial; light prefers light, dark prefers dark, the other variant is used only when its own is absent. Changing a model/summary does not change icon identity.

Assets: `builtin:zcode` contains a downsample of the repository-owned `packages/desktop/build/icon.png` (ZCode desktop icon); light and dark share the same PNG. Existing UI `Z.svg` is SVG and is deliberately not embedded as untrusted inline markup. Pi, Codex and Claude **do not** have a verified harness-specific raster asset/license in this checkout; do not substitute model-provider logos, material file icons, or invented branding. Their metadata icon fields remain unset and render a neutral initial until a licensed source is reviewed and packaged. No network fetch occurs from any manifest.

Boundary: this component provides a Node resolver and UI descriptor renderer, but does not add root DI, HTTP routes, asset packaging config or shell mounts (owned by other lanes). Composition must copy `packages/services/src/harness-assets/assets/zcode.png` into the runtime package next to the module or replace the resolver with an equally trusted packaged-byte provider; expose the descriptor through the host/RPC transport and pass it as the `resolveIconAsset` prop. Desktop and Web use the same descriptor without same-origin routes. Missing packaged bytes resolve to undefined and render fallback; they never fall through to remote URLs. The metadata constant is optional input to a later actual registry registration, not execution registration.

Acceptance: malicious ID/descriptor, oversize/malformed PNG, absent asset, light/dark, broken image and model switch must fail safely. No file paths, arbitrary URLs or inline SVG from a backend are consumed. No mutable session state or replay semantics are involved.
