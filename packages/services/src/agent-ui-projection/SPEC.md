# Canonical Host read projection (projection-replay)

The append-only committed EventJournal is the sole source of session history. Projector is pure: it turns one ordered, single-epoch prefix into V4 rows, control and usage; it never admits commands, runs tools or supplies invented backend events. History (`snapshotHistory`/`rowsRangeHistory`) and live reads consume the same projection. Journal cursor publication is the commit point: a concurrent append after a read starts belongs to the next read, never a partially read page. Desktop continuous delivery and mobile replayable snapshot/gap repair use the same sequence; neither uses UI-local state as execution truth.

Legacy child streams may have only a terminal `subagent.updated`, or repeat a terminal observation, including after a turn finished or in a later turn. Read projection retains a single finished row at the first observed terminal sequence, without inventing a start/execution timestamp. A repeated terminal may update its summary/metadata, never increment endedTotal again. Current started-child transitions remain strict: duplicate start, cross-child/turn collision, terminal updates of a running child outside its active turn, and a new unstarted child outside its own active turn fail. Terminal-only legacy facts may be read during replay after their own turn, but cannot establish a running child or authorize execution.

The pure usage transition now lives in the lower Host journal layer and is shared by admission and projection; the projection owns no alternate policy or accepted state. Host validates this transition before committing a new usage event, commits its derived index only after the durable cursor, and reconstructs it on open. Historical malformed semantics fail closed without quietly hiding any committed record; old journals are not silently migrated.

Usage accounting is keyed by `(turnId, sourceId)`. `usage.accounted` already declares `delta` (exactly once per call) or `absolute` (replacement snapshots of one call). A `usage.reported` without identity is legacy additive per event, readable only in turns with no `usage.accounted`; a mixed turn must carry explicit `sourceId` AND `accounting` on reports. Identical keys across kinds or duplicate delta keys fail closed rather than double count. Different source IDs sum; absolute snapshots replace only their own prior values. Omitted metrics remain absent in the usage ledger (zero is measured zero), including cache and reasoning units; V4's legacy cumulative numeric fields still encode absent metrics as zero; the additive `measured` flags on new external snapshots carry actual presence. No private reasoning text is projected by usage. A report without explicit accounting in a mixed turn is ambiguous and rejected, even when encountered before the accounted event.

Rows paging selects rowId `< beforeRowId` from one committed prefix. `atSeq`/`atRevision` describe that exact prefix, `atLogEpoch` fences stale UI pages; `hasMore` is based on eligible row count, including the oldest page. A live delta racing a history read must not change that page's watermark. Queries are read-only and repeatable, never prompt replay. Native V4 UI discards a page if epoch/directory revision/first-row cursor changes; the external Host UI accepts older same-epoch append-only pages across later full snapshots only when owner, cursor, source watermark and canonical first row still agree. Newly arrived Host tail rows always win on overlap. Consumers must not treat an old page as newer authority than a live row.

Acceptance: terminal-only/repeated/cross-turn legacy committed journal yields readable snapshot and rowsRange; malformed current child stream rejected; same/different call usage mixed and missing vs zero tested; >100k committed events and append during a page read yield oldest-page and consistent sequence/revision, no uncommitted tail rows.

## Cumulative presence migration

The committed usage ledger owns per-metric presence: a metric explicitly supplied as zero is present; omitted input/output/cache metrics are absent. The external projector publishes optional V4 `usage.measured` booleans alongside unchanged numeric cumulative values. Historical/native V4 frames without the field retain legacy numeric display behavior; UI must not label an external absent metric as measured zero. No SDK-default zero is evidence unless the committed event explicitly carries that metric. Desktop continuous and mobile replayable project the same journal; presence is not inferred in the renderer.

Host projector rows are append-only within one runtime epoch: stable row IDs can update in place, but no destructive rewind/reuse occurs without changing epoch. Since late terminal child summaries and long-turn updates can rewrite rows outside the live tail, the public external snapshot carries optional `rows.historicalRevision`, the greatest event sequence mutating any row before the canonical tail window. It is monotonic within a fixed epoch (even as rows age out of the tail); readers holding older pages revalidate the bounded held range on change. Native snapshots omit this metadata. `rows.firstRowId` is the earliest retained journal row, not the first tail-window row; it enables cursor pagination. Read pages return the actual source seq/revision, and a later same-epoch append cannot retroactively remove a preceding page. The renderer caps its cached rows at 2000; it does not claim unbounded history retention. A provider which rewrites earlier rows outside the overlapping tail in the same epoch cannot use this append-only contract without a new history revision.
