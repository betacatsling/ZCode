# Pi worker file tools (SDK 0.87.1)

Owner: the Pi worker owns turn/permission admission and keyed SDK wrappers; the parent Pi adapter transport owns at most eight per-call broker ChildProcess objects and native Bash operation lifetimes; each broker owns its pinned OS cwd and leaf descriptor from preparation to effect. The SDK owns the native tool loop and edit/read/write semantics via `create*ToolDefinition` with injected operations. Only `read`, `edit`, `write`, `bash` are active; custom definitions replace, not supplement, SDK defaults. Bash has its own explicit permission and **is not sandboxed**.

```
Host → parent adapter (worker + broker ChildProcess + SDK Bash operation ownership)
  → worker SDK tool_call → prepare immutable turn/input → parent starts broker pinned cwd/FD
  → interaction.requested (write/edit/bash only) → resolve same call/turn
  → SDK custom execute → parent broker FD IO / parent SDK Bash operations → SDK result
  └ deny/abort/terminate → parent closes/reaps; unexpected worker exit → parent aborts Bash,
    closes/reaps broker, then settles pending send as execution-unknown (not successful idle).
```

The worker pins the verified worktree root inode. The parent owns the broker ChildProcess and its exit listener; a worker request to the parent launches a broker, and later SDK operations use the same call-ID keyed child. Both closing and newly preparing children remain tracked until actual exit. For each operation it resolves input relative to the frozen session cwd, rejects lexical escapes, and spawns a fixed Node broker with the target parent as cwd. The broker verifies the actual cwd's ancestor chain by `..` against the pinned root device/inode **before** opening the leaf; each ascent is kernel directory traversal, not pathname symlink resolution. It holds the parent cwd and existing regular leaf descriptor while approval is pending. Symlinks/special files refuse; opens are `O_NOFOLLOW|O_NONBLOCK`. Read uses `O_RDONLY`, Edit uses `O_RDWR`, and existing Write uses `O_WRONLY` (matching the pinned SDK `fsWriteFile` permission requirement, including user-owned mode 0200 files). Write opens without `O_TRUNC` before approval, then writes and truncates the same FD only after allow. An absent write is only created by `O_EXCL|O_NOFOLLOW` after allow; SDK mkdir is constrained to the already-held directory. Concurrent mutations of a previously approved inode can still occur from other OS actors; this is not an isolation sandbox. If the parent is renamed after verification the broker remains anchored to the same directory inode. Unsupported platforms are refused by adapter probe/capabilities and fail worker boot before offering ambient-path tools (macOS-executed path; Linux source-gated but runtime not yet executed; Windows explicitly gated until process cwd/ancestor guarantees and tests exist). Model-facing mounted tool descriptions and guidelines explicitly limit operations to text-only regular files <=4 MiB with existing parent directories inside the worktree; read supports the native SDK offset/limit/truncation semantics. No images, no new parent directories, no nonregular files. Native Bash is separately approved but not sandboxed: SDK cancellation kills its detached process group; worker death requires a parent-owned lifetime cleanup receipt, not approval alone. Broker IPC is one bounded operation at a time, fixed executable and script, with empty inherited environment and no shell. Maximum eight prepared brokers per worker, file payload <=4 MiB; close on denial, abort, failed turn, detach/terminate, worker exit. No path or contents in diagnostics.

Review contract: the worker emits a permission summary derived only from its prepared broker entry, not directly from a later model input: workspace-relative target (bounded length), operation, UTF-8 input byte count and a truncated HMAC-SHA-256 of the complete serialized input using a per-worker ephemeral key. The approver can distinguish operations and compare payload fingerprints; raw contents never enter approval events or logs. The journal retains the relative path and opaque digest, so filenames should not be treated as secret from authorized journal readers. Read uses the SDK native definition but substitutes a worker-held root descriptor path (`/dev/fd/N`) solely for SDK read path resolution; injected operations still read the prepared broker FD, and neither the original path nor a swapped outside symlink is probed by the SDK resolver. No image reads. An unavailable descriptor alias fails closed. Broker close waits boundedly for actual child exit, escalates SIGTERM to SIGKILL, and reports failed reaping instead of hanging. The parent transport owns ChildProcess objects and actual exit receipts. Unexpected worker exit makes the parent reap brokers and abort the native SDK Bash operation (SDK SIGKILL to its detached group, followed by SDK child-wait settlement) before treating pending effects as resolved. Broker reaping and SDK Bash settlement have finite 1.5s failure limits; if either lacks a receipt, cleanup is reported as uncertainty rather than successful idle. Arbitrary detached grandchildren outside the SDK process group cannot be certified. Test-only Node handshake pauses the actual SDK Read after broker preparation and before the SDK resolver without a timer. It cannot authorize an operation and does not run in production. A write already underway cannot be rolled back.

Acceptance: real pinned SDK worker + Host and fake Model: Read, denied Write (no file), existing 0200 Write deny/no truncate then allow/shorter complete truncate (with outside sentinel), Edit, Bash, later turn reads changed content. Deterministic actual-worker Read prepare→resolver swap must see original bytes or fail closed without probing the swapped pathname; unexpected actual worker crash while new Write approval is pending must have a parent-owned broker child exit/close receipt and no created file, with no false idle. Input/turn admission asserted. Deterministic root/parent/leaf move/symlink and missing-leaf replacement races leave outside sentinel intact; aborted new write absent; FIFO refuses without blocking. Actual macOS execution, Linux execution separately reported, Windows unexecuted fail-closed.
