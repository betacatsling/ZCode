# Legacy native index and mapping

Native `tasks-index.sqlite` owns task metadata; the CLI session store owns the native transcript, queue, and precise session cwd/model where not provable from task metadata. The profile migration file owns **only** reviewed references (`source workspace key + native task id` -> target-verified project/worktree). A native directory projects current persisted rows into catalog summaries; it never admits commands or copies transcripts.

`index SQLite (WAL snapshot) -> full export -> target resolver (canonical cwd containment) -> pending or mapping -> verified durable SQLite backup -> same-source check -> sidecar publish`. Backup failure, source revision change, unrecognized raw task schema/migration, or ambiguous cwd/model refuse publication. Export includes closed, archived and deleted rows; `workspace_key`, not task id alone, isolates identical ids on distinct native scopes. Preserve exact original native scope separately from target worktree identity; an old subdirectory scope can map to a parent worktree with a target-proven relative cwd. The resolver proves exact native cwd containment/association and supplies its relative path; no local path fallback for remote identity. Unknown target/model/cwd remains pending. The public native metadata adapter reads an already-open `SessionStorePort.getSession` (`session.directory` is the resumed working directory), its latest `runtime/model_selection` entry, and a target-supplied scope-to-target lookup; it refuses out-of-scope or unverified target claims, and cannot mutate CLI history. A native entry with malformed explicit selection suppresses index-model fallback. If no native entry exists, the index's last-observed `providerId/modelId` is usable only when exactly one slash makes the encoding unambiguous; options absent remain absent. Exact cwd never comes from task-index `workspace_path` alone. The native index is never converted to a writable v2 session.

Backups are SQLite-generated snapshots (not a copy of live main file), fsynced and atomically renamed; verification checks the durable DB against its content hash and the same raw schema/export digest. Rollback verifies backup before deleting only the sidecar. Concurrent native writes can make apply fail; retry from a fresh preview. Catalog directory reads live native facts by scoped reference, missing rows stay absent. No native execution owner, replay stream, or accepted command queue is added.

Production metadata bridge: the CLI owns and migrates the session DB; Node receives the **already resolved** session DB path from the same bootstrap `getSessionDbPath(config, cwd)` source used by native startup (including custom relative paths), and opens only an immutable/read-only SQLite metadata view. The adapter checks the complete known migration ledger and required columns, and reads one session row plus its last model selection without scanning message/part bodies. Missing, malformed, future, or uninitialized DBs fail closed without creating/migrating files. The native sidecar never creates a CLI session or assumes a CLI-process object exists in Node. Explicit migration export/backup still takes a WAL-consistent full snapshot; ordinary sidebar facts read only selected task summary columns from the live read-only DB, validating schema each time. Stored pending interaction is not live waiting activity. On the next read, a committed WAL change becomes visible; no stale memoized snapshot is authoritative. A changed summary digest invalidates subscribers on that read; proactive refresh remains the native owner's event/DI responsibility, not an invented polling heartbeat.

A tree ID is `native:` plus a SHA-256 digest of target ID, original workspace key and native session ID; it is bounded independently of long remote keys. A collision between conflicting owner references fails closed. Original native scope and ID remain separate on the navigation descriptor; tree ID is **never** sent to V4 as a native task ID. Async `resolveOwner` matches the full target/workspace/scope/native ID and yields an exact target-verified owner descriptor, or undefined. The native catalogue advertises ZCode metadata with a distinct native V4 transport type; it is not registered in the external HarnessAdapter execution registry. A joined native/external complete session index rejects duplicate tree IDs and preserves each source's stale/offline freshness and unknown activity rather than guessing idle. Changes originate with source owners; the join only relays invalidation.

```text
CLI native session DB (sole writer, startup migration) → read-only SQL metadata view
native tasks DB (sole writer) → read-only summary projection → mapping join → native tree ID + original V4 ref
external Host journal (sole writer) ───────────────────────────────┘ joined catalog index
UI navigation descriptor → original native V4 owner/lease/commands (never external Host queue)
```

Acceptance: actual disposable SQLite DB including WAL updates, closed sessions, custom resolved DB path, malformed/future schema and selection; nested original scopes and duplicate native IDs across two targets; long remote identity yields valid bounded tree ID and exact original navigation; stale stored waiting does not claim live waiting.

Acceptance: disposable WAL concurrent write before backup/revision mismatch; restart/verify and backup corruption/failure prevent mapping; unknown raw schema refuses normalized export; actual Git subdirectory path maps to the verified worktree root while retaining native subdirectory scope, remote or ambiguous cases remain pending, same task ID in two native scopes never joins the wrong target.
# Catalog recovery decision

The profile file owner alone writes profile catalog metadata and durable intent. Target remains sole authority for repository operations: `intent persisted → target operation once → target lookup by stable ID → profile commit → clear intent`. A failed target call or profile write leaves intent and **never repeats Git**; caller must invoke explicit recovery after target lookup. An unmounted lookup remains blocked; no native fallback. Unknown target/offline/mismatched generation remains blocked, not classified as absence. A target result obtained via query must match the original binding, target and immutable workspace identity, not just path. All mutations wait behind the profile owner's serial queue, and a pending operation blocks competing mutations. Crash after target effect but before profile commit is reconciled from target's durable ID directory. Import registration follows the same rule. No tab-derived imports, compensation, or runtime business state in profile.

Lock recovery is explicit: exclusive recovery marker serializes inspection, checks previous PID dead, then removes only the observed stale lock token. A replaced lock cannot be unlinked; writer checks its token before every commit and close. A corrupt/unknown owner fails closed. Archive: target deny precedes profile archive; profile unarchive precedes target allow. On restart, explicit policy reconciliation must run before admissions; partial fanout is denied until verified. Native migration public contracts are read-only and copied from the native-index lane; SQLite remains that lane's owner.

Catalog stores one optional schema-v1 pending intent in the same atomic profile file. Import, adopt, create and removal persist it before target mutation; known-unsafe removal preview rejects before intent. A target failure after intent is execution-unknown and freezes profile mutations; `reconcilePending()` only reads target facts for matching stable IDs/ownership and commits the profile once. Missing recovery lookup and target offline reject; no retry of target create/remove. Archive denial stores an intent before target policy writes; recovery repeats only idempotent denial then publishes archived metadata. Unarchive publishes metadata before allowing admission; an allow failure remains denied until explicit `reconcileArchivePolicies()`. The composition owner MUST run pending and archive reconciliation before serving admission, keeping target deny gates in place across the restart. A profile commit's rename-before-fsync ambiguous failure is resolved by reading the disk first, not appending another target result.

Known integration limits: the target bridge in this checkout does not yet supply the optional durable `lookupBinding`/`lookupWorkspace` port; therefore execution-unknown target creates cannot recover in production until its owner adds trustworthy target-local read projection (including original Catalog DTO metadata). No Catalog-local reconstruction from Git path is permitted. A native SQLite reader exists only on the other native-index lane; this lane does not claim that reader mounted. Legacy lock files predating PID/token format cannot be safely auto-recovered. Malformed/unknown lock ownership requires explicit operator inspection.
