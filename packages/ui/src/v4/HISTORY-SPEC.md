# External Host bounded history browsing

Host journal and projector own committed rows. Renderer owns only a bounded contiguous viewing window (at most 2000 rows), its cursor and whether it follows the live tail; it never admits a second history or replay queue. A full Host tail snapshot updates control/usage and overlapping rows, but must not evict the held historical window or starve an in-flight earlier read. At the cap, an earlier page shifts the viewing window towards the beginning (evicts newest rows); this is **not** end-of-history. Newer navigation walks back through Host rows/range, and Latest explicitly reacquires a fresh authoritative tail. `firstRowId` is the journal's first row, not a local budget marker. Unloaded gaps must not be drawn as contiguous content. Native V4 snapshot/delta rules remain unchanged.

`rows/range` beforeRowId is an exclusive cursor, with sequential Host row IDs. Newer traversal requests a bounded range ending beyond the current last ID and selects only strictly newer rows; a short last page cannot imply end of history unless it reaches the current Host tail. Pages and snapshot changes are fenced by subscription generation, epoch, firstRowId, owner identity and read cursor. A historical view keeps the live control/usage facts but doesn't append distant tail to displayed rows. Loading latest is a view action, not a prompt resend. A changed old row within the viewed page must be refreshed from authority, not assumed immutable: the projector allows old terminal child metadata updates. The Host projection reports an optional monotonic `rows.historicalRevision` (latest event sequence mutating any row older than its live tail); native snapshots omit it. When it advances while browsing, the renderer re-reads only its bounded held window through Host rows/range, fences responses by generation/epoch/first-row/cursor and coalesces concurrent invalidations. Normal mutations inside the authoritative live tail do not invalidate an older held read. This is a coarse range invalidation (may refresh a disjoint old view) rather than a claim that older rows cannot change.

Event order: Git Target → Catalog → SessionHost committed journal → public RPC rows/snapshot (desktop-continuous live, web-remote-replayable recovery) → renderer view cursor/window. On owner/lease/epoch change abandon in-flight pages and view mode. Tests: cross 2000 repeatedly to earliest while active stream continues, move forward and jump to latest, old row mutation while page pending, explicit usage zero versus absent; browser desktop/mobile shows navigable controls. The public RPC accessor and desktop attachment must expose the already registered `IProjectCatalogRpcService` and `IWorkspaceHierarchyService` from the same Core ServiceCollection; the Shell cannot infer them from renderer-local fixtures. Both descriptors remain Core-owned; no renderer service proxy may manufacture rows or owners. Finite isolated real Core/RPC/Shell test is required separately from controlled services. Native creation remains fail-closed until CLI-owned durable draft receipt and verified mapping exist.
