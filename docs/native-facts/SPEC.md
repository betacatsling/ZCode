# Native production facts (bounded read bridge)

The native CLI owns V4 session creation, command admission, activity and its SQLite session facts. The task index owns scoped `(workspace_key, task_id)` summaries; migration sidecar owns verified target/workspace/generation mappings. The bridge never opens a startup store or initializes a missing DB, invents a default session DB path, infers activity from a persisted status, or creates another executor. The caller supplies the *actual configured absolute* native session DB path resolved at native bootstrap (`getSessionDbPath(config, cwd)`); task-index DB path is likewise supplied by its owner. Both are read-only here. Missing or malformed schema fails closed.

For local V4 sessions without `workspaceID`, exact `directory === source workspace path` is an attestable scope; an ancestor directory containing the cwd is not. For remote, `workspaceID === source workspace key` is mandatory. For local sessions with explicit workspaceID, it must match source key. Missing scope or scope mismatch means pending/read-only; never attribute the ID to another worktree. A mapped row must be rechecked against the current native store and index before navigation/listing, including the exact target and worktree generation captured by migration. Model selection remains the native store's fact; malformed explicit selection cannot fall back to the index. Target's current generation check remains the hierarchy/Target admission owner's obligation.

Event order: native CLI commits summary + session → bridge reads read-only index, mapping and native session facts → navigation resolves scoped original ID → live port performs V4 create/capabilities or reports activity/fence. Index reads do not start CLI, admit a turn, or derive idle from SQL. The live port must be supplied by the native runtime owner, never implemented as a zero-count stub; offline/unknown activity fails maintenance/removal. A successful fence is held until the caller releases it. Desktop continuous and mobile replayable attach to the same existing V4 owner rather than this projection.

Acceptance: two same-ID local nested scopes cannot cross-bind, remote identity cannot bind by path, stale/missing facts are not runnable, read-only DB/index can list without a startup/open side effect, original ID and generation survive the join, and live activity/fence are forwarded without replacement.
