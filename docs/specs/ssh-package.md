# SSH target attachment and Linux release closure

Owner: persistent target Core owns sessions and runtime; SSH backend owns only a disposable forwarding channel. Packaging runs locally, never copies HOME, credentials, repo or user configuration. No per-Harness SSH Host. Desktop must provide expected installed server ID and version; missing identity fails closed. A one-use Host ticket comes from the *tunneled loopback* endpoint after checking server info protocol/version/ID/capabilities. The tunnel and ticket are not a daemon; closing either must not stop Core. Disconnect is not a task cancellation.

Order: validate target environment linux-x64/arm64 → stage archive containing exact Node 24.14.0 and built CLI/Core/Pi/Agent plus runtime dependencies/assets → verify each shipped symlink stays in release root and each entrypoint exists → upload/install using existing remote backend → short `serve --daemon --json` exec → open local loopback SSH tunnel → validate server-info expected identity/version/protocol → request one-use ticket → caller upgrades promptly. A failed check never requests a ticket. The same installed Core is reattached; no second admission/owner. Retry only a new attachment ticket, never replay a task command. Desktop continuous and mobile replayable are separate routes to one Core.

Acceptance: an isolated staged Linux release starts fake CLI and fake Pi worker with *only* shipped files; mismatched Node, missing runtime entrypoint, escaped symlink, incorrect server info, failed launcher or expired ticket fail closed. Tests use fake endpoints and temp roots, never remote machines or paid providers. Native binaries require a real target-Linux smoke before claiming target execution.
