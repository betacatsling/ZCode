# Paired phone attachment and remote scope boundary

Default OFF. Desktop user enables and explicitly consents to one workspace on the current window-scoped Host. Main owns bounded one-use challenge/device lease; Host owns method/argument/event projection on each attachment; Core owns session/accepted command/journal. Phone browser carries only a device credential (never the Core ticket), connects over authenticated origin/CSRF-bound transport, and receives replayable snapshot + gap events from the same Host. Non-loopback deployment requires TLS/WSS. Revoke, expiry, Host replacement or window close closes live views and blocks all future effects; never stops Core business work. Reconnect to the same current Host resumes the same session and interaction request ID, never resubmits input. No account stub may masquerade as authentication.

```
desktop consent → Main one-use challenge → device lease → Host-scoped replayable port
                                                      → Core session/journal (only business owner)
phone disconnect → journal continues → authenticated reattach → snapshot + cursor gap
revoke/rotate → close views; stale requests denied, Core run untouched
```

Security design for production attachment (not the existing consent helper): Main may mint a one-use device lease after an explicit, sender-bound desktop consent; the HTTP/WebSocket upgrader must compare the actual `Origin` header to its configured origin and reject credentials in URLs. The browser never chooses `windowId`, Host handle, or identity. The Main-provenanced, Host-validated phone scope must bind the captured local workspace path, canonical identity key, **selected existing Host session ID**, and a revocable generation. The currently implemented Host discriminator is NOT itself an authorization credential or a production entrypoint; without a sender-bound Main consent and authenticated browser upgrader it must stay unreachable from browser clients. On _each_ RPC request and event subscription, Host must check the active generation and explicitly allow the method; arguments containing workspaceId/sessionId/taskId must be certified against the actual Core Catalog and session ownership before effect, then generation checked again after any await. Only AgentHost session read/dispatch and workspace hierarchy owner/catalog/capabilities for the selected Host session may be exposed; unknown methods and global service channels are denied, not forwarded to the window-wide port. Subscriptions must filter events before delivery, not merely close on revoke. Main only owns lease/transport, Host only owns scope, Core owns accepted commands and replay cursor. If Core cannot certify an ID, deny it rather than guess from the requested path. A production route is NOT enabled until these checks and a joined browser test are present.

For existing remote hierarchy create, the renderer-supplied workspaceId is NOT authority. The target Core Host availability target ID and hierarchy's Catalog-backed resolved workspace must match captured attachment path, identity and target BEFORE createAgent; the Host registry separately certifies the remote session/generation (target Core need not know Desktop's remoteSessionId). After any async read Host checks current registry generation again immediately before the effect. A potentially accepted call or lost ACK is uncertain even with an unchanged generation: no retry; only read-only stable command recovery once provided by Core. Returned owner validation remains a separate post-effect safety check, never a substitute for pre-effect authorization. All other phone-exposed service methods must be explicitly scoped or denied; generic window port is forbidden.

Acceptance: actual two-workspace Core fixture must show wrong ID causes zero foreign creation/input/model effects; same-path foreign identity denied. Stale generation during lookup and after admission denied/uncertain without resend. Browser via actual authenticated port and shared Shell/Pi, active revoke and replayable gap recovery must pass before this feature is called delivered. Desktop-continuous checked independently. Native create metadata is selection/provenance, not authentication; production Native join is separate from local phone delivery.

## Connected one-session transport decision (PHONE_TRANSPORT successor)

Main owns only explicit window-scoped enablement, one-use challenge and expiring device lease; selection is supplied by the desktop UI but **certified against the existing window Host's actual Core** before Main creates a challenge. An enable request reserves an epoch before awaiting certification: disable, window close, Host replacement and any subsequent enable invalidate it. A stale certification may not start a listener or mint a challenge; an already opened listener is closed before returning failure. A failed reauthorization leaves the previous selection revoked (fail closed), never silently restores it. The selected `hostSessionId`, `workspaceId`, canonical identity key (`workspaceIdentity?.trim() || workspacePath`) and Host object are immutable on the grant; a new selection revokes the old credential. The browser never chooses these facts. Main binds actual request Origin to the listener authority, rejects cross-site navigation and state changes without a CSRF proof, accepts a challenge only in a bounded POST body, issues HttpOnly SameSite device cookies, and requires the same device plus a separate CSRF value for WS upgrade. The credential and challenge never appear in URL, argv, environment or logs. The unauthenticated page has no Core/task facts and both HTML and build assets carry no-store, no-referrer and restrictive CSP headers. A revoked socket must close immediately; its scoped port and subscriptions are disposed without stopping the business task. Local cleartext is allowed solely on an explicitly selected loopback listener for synthetic tests; production nonloopback requires TLS/WSS and a configured trusted origin (not a client-provided header). No generic `/ws`, Core ticket or full ServiceCollection is forwarded.

```text
desktop user selects mounted owner -> platform hook -> preload sender-bound IPC
 -> Main obtains current utility Host, opens temporary *phone* port
 -> Host queries Core Target/Catalog/stored selected spec (no command) -> Main seals scope
 -> Main consent/one-use POST -> device lease cookie -> authenticated WS
 -> Main current Host/lease check -> existing Host phone MessagePort -> narrow RPC
 -> Core CommandInbox/journal -> replayable browser projection and shared pane
phone disconnect -> close only port -> Core continues -> new authenticated port -> snapshot + cursor/gap
revoke/expiry/window or Host replacement -> close active WS/ports; never cancel Core task
```

On each read or command the Host checks actual owner, scope and live port; on event subscriptions it filters the same session. The phone hierarchy RPC is read-only and limited to resolveOwner/capabilities/listHarnesses/asset for that selected owner; all other hierarchy methods denied. Catalog data (including icons) must not reveal any foreign session or workspace; opaque asset IDs must first be proven to belong to selected harness entries. Desktop `desktop-continuous` remains unchanged; browser uses `web-remote-replayable` snapshots, earliest gap and rowsRange rather than resending admitted commands. Any uncertain accepted dispatch is queried by original command ID, never automatically retried.

Acceptance for this milestone: production caller reachable from desktop, separate browser consumes public client and existing ExternalSessionPane; actual disposable Core/Pi/fake Model positive input/final/usage and held stream reconnect/same interaction/revoke, with foreign/stale/expired/replayed/Origin/CSRF denials **before** Core input/Model effects. TLS deployment/physical phone, full hierarchy and Native remain later full-goal requirements. A helper-only or disabled-by-default test fixture is not accepted as the connected milestone.
