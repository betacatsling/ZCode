## Meaningful producer and bounded lifecycle (required before full run)

A seed counts only canonical turn-owned entity events that represent bounded, distinct assistant messages or tools (e.g. `text.delta` followed by `message.finished` with matching unique `messageId` under the admitted `turnId`). A repeated unknown `extension.event` is not historical content. Preserve an early `tool.started` with its original `turnId`/`toolCallId` and finish it only after a newer append; the original tool row must change in place. Capture kinds from actual emitted validated events, reconcile the total against Core's committed sequence, and read projected row count, open/closed turn/tool facts from Core. Total full-case events, including append and control, stay below 102000. Text payloads remain small and meaningful; no 100k irrelevant no-ops or giant payloads.

`SessionHost.dispatch(send)` admits then tracks the adapter's pending Promise; the adapter Promise is the _owned run lifetime_, not the dispatch ACK. The single producer must yield at finite batches to the durable Host, be cancellable during production or any of three paused phases, and resolve its run after cancellation with an original-turn terminal `turn.finished(cancelled)` where the Host remains live. Terminate/shutdown stop emission, unblock barriers, and await that exact run's settlement before closing the Host; no detached/unhandled producer or post-disposal event. A new send cannot reuse this session. Cancellation is verified through a genuine accepted Host command and committed terminal, not a private release masquerading as control. A short joined UI diagnostic and a separate short control/disposal case must pass before either authorized full test. On failure preserve exact facts and do not repeat a full run unchanged. After the author positive-path full run, cover the fixture's additional teardown races with short controlled cases: cancellation while the final durable-seed read is suspended _before_ the first barrier registration must not register an unwakeable barrier; cancellation after original tool success must not emit a second `tool.finished` for that same ID. Terminate and Core shutdown must stop/reap the exact run and leave no later events. A test-only checkpoint may pause the producer after the real durable read but before it returns; it is not a journal owner, command, or time-based correctness mechanism. Assert both the accepted Host command receipt and persisted terminal event counts. These edges do not invalidate already recorded normal-path 100k evidence but must be closed before lifecycle acceptance.

```text
Core Host dispatch(send) → durable command receipt → adapter run Promise (tracked by Host)
                                          ├─ batched validated event → durable journal → rows/revision
Core Host dispatch(cancel) → adapter stop → unblock barrier → turn.finished(cancelled) → run settles
Core shutdown/terminate → adapter stop + await exact run → Host close (no later emissions)
```
