# Mounted load validation (§10.2 / §13.8)

## Scope and authority

This is a **gate runner**, not certification of the current checkout. The only durable session/event authority is the target Host; Project Catalog owns project/workspace references, target WorktreeService owns worktree facts; the mounted Shell/ProjectSidebar/SessionPane owns only focus and drafts. The runner owns disposable fixture paths, schedules and measurements, never business state. Do not launch Desktop/Web with real HOME or userData. The runner requires a caller-supplied production driver module; no detached-tree/Button fixture or in-memory substitute may pass the mounted gate. No paid provider or SSH use.

```text
runner → disposable tiny Git repo → target Git discovery (read-only)
       → production Catalog/Host admission → synthetic Harness events → durable Host journal
       → actual mounted Shell/ProjectSidebar/SessionPane → browser interaction samples
       → owner counters + cleanup/reconnect facts → artifact manifest
```

Each session has unique command/turn identity. Send/admit once; detach only removes subscription. Reconnect queries/replays Host journal by cursor, never resends prompt. Host epoch and session identity fence late events. Desktop continuous and Web remote replayable are distinct delivery modes: record both separately; do not interpret connection interruption as session completion. No timeout-based sync: wait for explicit owner sequence/cursor. Fail if unknown, offline, or gaps are presented as caught-up. Counters come from owner calls, not DOM heuristics. A false observation or missing counter is a failure, not zero.

## Contract / fixture

`scripts/e2e/multi-harness/load/runner.mjs` exports `runLoad({driver, delivery, durationMs, eventCount, worktreeCount, sessionCount, expandedCount, reconnectEveryMs, sampleEveryMs, idleMs, artifactBase, baselinePath, sourceCheckout, buildArtifactPath, mode, benchmarkDatasetId, isolateProcessEnv})`. Driver is loaded via `--driver <absolute .mjs>`; acceptance through the programmatic API requires `isolateProcessEnv:true`. The CLI strips inherited environment except a small process/locale whitelist and isolates HOME/XDG/data paths before importing the driver, then switches to the run-specific paths before `open`; acceptance through the programmatic API does the same before `open`. This does not grant permission to contact a live Provider; the driver must enforce no-network/no-account use. The smoke CLI requires explicit `--duration-ms` and `--events`; benchmark mode requires `--benchmark-dataset-id <stable-id>` and explicit `--duration-ms` and `--events` (other scale flags: `--worktrees`, `--sessions`, `--expanded`, `--sample-every-ms`, `--reconnect-every-ms`, `--idle-ms`, `--max-backlog`, `--max-owned-children`). The runner does not import mutable product internals. A production driver must implement `dispose()` and `open({root,repo,worktrees,artifacts,isolation,mode,registerCleanup,registerChild})` returning:

- `mount({expandedWorktrees, sessions})`: create 10 distinct **synthetic runtime** sessions across ≥5 expanded workspaces through actual production Catalog/Host and mount the real Shell + ProjectSidebar + SessionPane. Return `{ mountedSurfaces: ['Shell','ProjectSidebar','SessionPane'], owner:'durable-host', delivery:'desktop-continuous'|'web-remote-replayable' }`; do not return this metadata unless independently verified. Acceptance additionally requires `mountEvidence:{shellVisible:true,sidebarVisible:true,paneVisible:true,hostJournalReopened:true}` verified through real mounted page selectors and read-after-reopen durable Host query; no Button/detached tree substitution.
- `discover({repo, candidates})`: read-only production target discovery; return stable candidate IDs (including main), no Agent start, no Git mutations. Worktrees passed to mount are the discovered real paths.
- `emit({sessionId, eventId})`: inject one synthetic Harness event into the **real durable Host**; resolve only after committed sequence. No paid Model calls.
- `sample({sessionId})`: perform a real typed-input + session-switch interaction on the mounted page, returning `{typedInputMs, sessionSwitchMs, focusStable, draftStable, selectedStable, worktreesStable}` measured from browser interaction to painted response (not RPC response).
- `detach()` / `reconnect()`: sever and restore client attachment, not Host. `reconnect()` must query the owner journal, return `{replayedWithoutResend:true, caughtUp:true}`.
- `facts()`: return `{durableEvents, backlog, backlogHighWater, implicitCliStarts, fullHistorySidebarReads, worktreeMutations, childProcesses, acceptedPrompts, focusStable, draftStable, selectedStable, heapBytes, rssBytes}` from instrumented owner + process metrics; all numeric fields finite nonnegative, booleans true. `backlog` is committed minus UI-consumed event sequence, not history row count. `backlogHighWater` is the owner-observed maximum between calls (not just the sampled maximum). Default bounds: backlog high-water ≤10,000 and at most 32 owned child processes at any point; configurable (`maxBacklog`, `maxOwnedChildren`) only with explicit comparable baseline/load documentation. Acceptance requires separate `processes.host` and `processes.renderer` `{heapBytes,rssBytes}` samples while mounted, both >0, and `processes.host` after cleanup/idle. Renderer may have exited after close. Never present runner heap as product heap; aggregate heap/RSS fields must explicitly represent measured product processes, not the fixture runner.
- `gatewayProbe?()`: optional local Fake Provider **pure ingress→executor→egress** adapter samples in milliseconds; no live Provider traffic. Omit if unavailable and mark unsupported.
- `close()`: explicitly close mounted client and synthetic sessions/children without terminating unrelated processes. Subsequent `facts()` must show zero owned child processes; idle memory samples must be taken after cleanup. Driver must not modify global account/config data.

All counters are run-scoped, not global history; all hooks must return truthful production instrumentation. No production driver is shipped at this checkpoint; a missing driver fails closed. Driver version + production commit + shell/Host provenance must be placed in `metadata` by `open` for review. For comparable runs, the runner independently reads `sourceCheckout` Git HEAD and hashes `buildArtifactPath`; these must remain available to recheck the baseline when running the candidate. Tests use a labeled **contract stub** solely to test runner invariants, never to claim mounted success.

## Gate, evidence and failures

Run `--delivery desktop-continuous` and `--delivery web-remote-replayable` as **separate** isolated acceptance runs with their own matching baselines; a single delivery result does not certify both paths. Defaults: ≥50 _real_ worktree candidates from a newly initialized disposable tiny Git repo (never this project repo or any artifact base inside a Git checkout); 10 sessions in ≥5 expanded workspaces; ≥100,000 committed events; ≥8 hours elapsed monotonic clock and ≥60 seconds idle after cleanup. Attempts to call `--mode acceptance` with lower minimums fail before any Git/process launch. `--mode smoke` allows smaller duration/events, always reports `smoke` even if all counters pass. Every run creates a fresh temp directory; no cleanup of pre-existing directories. A rejected preflight (invalid mode/minima, absent driver, or artifact base inside checkout) must not create directories under the checkout; a run that passed preflight writes `result.json` even on gate failure. Driver exception messages are not copied into artifacts or stdout, only the failing gate phase. The output records a status (`smoke-only`, `failed`, `load-measured-baseline-pending`, `latency-baseline-pending`, or `latency-measured`; never automatic product certification), reasons, elapsed, counts, owner-observed event backlog high-water/final, typed/switch p95, time-series heap/RSS (including post-idle/cleanup), process counts, provenance and unsupported checks. Acceptance samples must include ≥20 **typed-input and switch measurements per session**, recording both measurements against the same session ID per interaction; reject missing IDs and incomplete coverage, not merely ≥20 globally. Benchmark uses the same >=20/session floor and an explicit deterministic measurement plan: session IDs in stable round-robin order, one initial sample per session followed by scheduled rounds and one terminal round at/after the window boundary. Both runs must record the same schedule (relative planned windows, not wall-clock actual paint latency), exact per-session population and counts, with measured timestamps in their declared windows; no opportunistic samples from faster runs may change p95 population. A short smoke never satisfies comparison. Missing baseline means regression **unmeasured**, never ≤10%. Compare only explicit benchmark runs using preserved baseline worktree/commit on same machine and _same config/driver/load_ with a different preserved baseline commit, separately for typed and switch p95; nonmatching baseline is rejected. The explicit runner regression budget is +10% per p95 and an over-budget run fails; agreeing on this budget does not certify the baseline or production. Separate Fake Provider adapter-only latency from live Provider compatibility (not measured here).

During setup: derive isolated HOME/XDG and Desktop userData and Web browser profile **inside the new artifact root**, prove realpaths are descendants before any driver launch; pass the paths into `open`; driver must attest the effective app/browser paths and must reject otherwise. No regular HOME, credentials, inherited provider keys, production server endpoints, SSH, or real accounts may be used. Driver must refuse to run if mount/runtime hooks are unavailable. Artifacts must not contain credentials, prompts or endpoint URLs.

Short contract tests: `mise exec -- node scripts/mise-run.mjs pnpm exec node --test scripts/e2e/multi-harness/load/*.test.mjs` (if pnpm dependencies absent, `mise exec -- node --test scripts/e2e/multi-harness/load/*.test.mjs` uses only Node/Git). Production gate command after mounted integration is stable and driver is implemented:

```sh
# In MAIN, from the integration checkout; run as a background job managed by MAIN, not a child agent.
# bg_run(command="mise exec -- node scripts/mise-run.mjs pnpm exec node scripts/e2e/multi-harness/load/runner.mjs --driver /ABSOLUTE/ISOLATED/production-driver.mjs --mode acceptance --delivery desktop-continuous --artifact-base /ABSOLUTE/DISPOSABLE/ARTIFACTS --baseline /ABSOLUTE/BASELINE/result.json --source-checkout /ABSOLUTE/PRESERVED/CANDIDATE/CHECKOUT --build-artifact /ABSOLUTE/PRESERVED/CANDIDATE/BUILD/FILE --build-provenance /ABSOLUTE/PRESERVED/CANDIDATE/PROVENANCE.json", timeout=32400)
```

Driver and baseline are required for production certification; the above is an invocation _template_, not a claim those files exist. All nontrivial commands must go through the absolute shared heavy-slot wrapper with internal fanout one; eight-hour jobs require MAIN's dedicated reviewed resource window, never silently bypass the wrapper in a child lane. The measured build path names a file listed in the preparation manifest. The baseline preparation command below is finite and does not launch a Provider or Shell:

```sh
mise exec -- node scripts/e2e/multi-harness/load/prepare-baseline.mjs --checkout /ABSOLUTE/.worktrees/multi-harness-baseline-prep --artifact-base /ABSOLUTE/DISPOSABLE/BASELINE-PROVENANCE --execute
```

It invokes each build step through the absolute heavy-slot wrapper, serially (`@zcode/adapters... -r build --workspace-concurrency=1`, then Desktop build metadata, tsup, vite). Dependencies must already be available offline; the command never installs from network. Actual baseline checkout `1e7c0e2` was built in an ignored output directory: all four steps exited 0, 6,724 hashed ignored output files, identical clean pre/post tracked source commit; local evidence is `/private/tmp/zcode-load-baseline-provenance/baseline-build-provenance.json`. It is **built-unmounted**, not a measured full-Shell baseline: the old checkout has no `scripts/e2e/multi-harness/load` runner or Host/Catalog/external-owner mount. A standalone Sidebar fixture cannot replace the old Shell for regression. If a comparison needs an earlier product implementation with an equivalent driver, MAIN must first preserve and verify that source and repeat this build/provenance process; never label a candidate-only measurement as a baseline. Reserve isolated hardware windows: run candidate 8h stress for each delivery; separately run short fixed-window benchmark baseline and candidate serially for each delivery using identical declared dataset and load, then inspect all result.json files. The benchmark must not be represented as an 8h gate. Do not run a second broad build/browser load concurrently. Unavailable mounted driver, absent comparable baseline, or missing Desktop/Web isolation proof are explicit product gates, not skips declared green.

## Repair contract: partial-open ownership and latency comparison

Before calling `driver.open`, the runner owns a cleanup registry. The driver exposes a **top-level `dispose()`** that can be called even if `open` rejects (idempotent across `mount.close()` and partial launch). `open` receives `registerCleanup(fn)`; register a cleanup function _before_ any asynchronous launch and invoke it once at teardown, last-in-first-out. Immediately after spawning each real child, call `registerChild(child)` before any await or fallible work. Even if `open` throws, the runner drains the cleanup registry, calls `dispose()` (with failure-only deadlines), and verifies all registered children have emitted `close` with a real exit; it signals a stranded registered child and marks the run failed rather than trusting a `childProcesses:0` report. Mount `close()` remains required on success. No unregistered child launch or fire-and-forget process is allowed. Cleanup failures are phase-only diagnostics (no stderr/secret output). Resource ownership order: runner registry established → driver registers disposer → child launch + immediate child registration → open/mount → close → registry drain + driver dispose → child close proof → post-idle facts. An absent mount on partial-open cannot supply owner counters; cleanup evidence reports only registered child exits, and the run fails.

Latency comparison is independent from the long-stress minimum. A preserved baseline source checkout must exist outside the artifact tree with clean tracked files, at a different Git HEAD from the candidate; the runner reads Git HEAD independently for **both** checkouts and matches each against the claimed commit, instead of trusting baseline JSON. Record/compare hardware fingerprint, delivery, fixture/load config, idle window, measurement window, driver version and independently hashed build artifact (a binary hash alone does not prove the binary was compiled from the claimed source; release certification also needs trusted build provenance). An explicit p95 budget of at most 10% applies separately to typed input and session switching; over-budget fails. A repeatable shorter benchmark baseline is valid only against a candidate benchmark run with the same controlled dataset, load and measurement window; both remain latency evidence, never an 8h stress result. The runner owns the round-robin sample plan (fixed count derived from declared window/cadence, not emitted-event throughput), session ID ordering, scheduled window labels, and count/coverage validation for BOTH interaction types. Actual elapsed observations can vary within the planned window tolerance, but samples outside their slot or missing sessions are incomparable. This does not manufacture product paint timings. Genuine candidate stress remains >=8h per delivery (not 32h as a single-run minimum), >=100k events and the stated fixture/session minima. Baseline source and artifact identity must remain preserved for independent audit; no auto-adoption of rebuilt same-path source. Missing provenance or inconsistent claims are incomparable and not certified.

## Driver join and baseline preparation (load-comparability)

`driver.open` receives explicit `delivery`, `sourceCheckout` (realpath of checked-out driver source, not process.cwd), and build identity arguments; no argv inference. The runner rejects artifact bases inside either its own or the driver's actual checkout. Top-level driver `dispose` is idempotent and owns partial opens; register cleanup before an asynchronous owner open and dispose in reverse order after normal close. Runner owns child reaping and artifact. Driver remains fail-closed at real Shell/Sidebar/Pane mount, sample and process facts: service journal and empty extension events are not active conversations/renderer delivery proof. No production account registry is imported or used by this fixture; default app startup remains untested here. Do not attribute driver service cursors to browser UI.

Baseline prep uses preserved `multi-harness-baseline-prep` Git HEAD with clean tracked sources and an explicit pinned build invocation. Pre/post capture HEAD, tracked status, tool versions, exact command/exit and log hash, actual artifact realpath/hash; output artifacts must be ignored/untracked and tracked product source unchanged. A hash by itself cannot prove the build derivation; store a manifest tying the verified pre/post checkout and invoked command to the artifact, and reject failed/missing build outputs. Non-test production benchmark requires `--build-provenance` for both runs; runner binds a preserved manifest's source commit, post-build commit, successful build command steps and matching named build artifact digest before comparing p95. Test-only contract-stub measurements never certify a product baseline. MAIN must serially run baseline/candidate benchmark for each delivery on the same machine and separate candidate ≥8h stress for both. A Sidebar-only fixture is not an old full Shell implementation. No paid model calls or unattended eight-hour run in this lane.

## Deadline and split-gate contract (load-deadline-latency)

Runner owns the cleanup deadline and registered child exit proof. Event order: open registers cleanup and real children → optional mount.close → LIFO registered callbacks → driver.dispose → registered child SIGTERM, then SIGKILL if needed, and await actual `close` event → only on fully proven cleanup, post-cleanup and idle owner facts. A hung close/callback/dispose times out as **failure only**; the runner still reaps registered children. Never turn a timer into an exit proof or into a successful owner/sync observation. Partial open has no mounted facts; no post-cleanup owner claims may be invented. No new driver methods. The emergency deadline is fixed by the runner, not caller-controlled acceptance criteria.

Run latency as explicit `mode:benchmark` with a nonempty stable `benchmarkDatasetId` and fixed `durationMs` window. The benchmark is a separate run using the same driver hooks and actual mounted samples over that window. Comparable baseline and candidate must each be benchmark runs with identical delivery, dataset ID, duration/window, event count, fixture/workspace/session distribution, cadence, limits, idle duration, machine and driver version, independently preserved different source commits and build hashes, nonempty samples and valid p95. A baseline measured in smoke or acceptance is incomparable, even if its config happens to match; neither benchmark nor smoke certifies stress. The runner must validate its own candidate benchmark measurement before comparing it with the preserved baseline: extracting the baseline comparator into another module must not remove the local measurement validator import, nor turn a runtime ReferenceError into missing or successful evidence. A result without comparable baseline is `latency-baseline-pending`; within +10% on **both** p95s is `latency-measured`, over budget fails. Acceptance stress **independently** requires 8h/100k/50/10/5 per delivery and reports `load-measured-baseline-pending` (meaning no latency certification in that artifact), never claims latency from its duration. Two candidate 8h runs (one per delivery), plus two short baseline/candidate benchmark pairs, can provide the two independent kinds of evidence; no four 8h runs are required. This does not waive production driver, provenance, or baseline requirements. Benchmark `durationMs` is measured monotonic elapsed time, not a sample count proxy; empty/invalid windows and missing/mismatched measurement provenance fail closed.
