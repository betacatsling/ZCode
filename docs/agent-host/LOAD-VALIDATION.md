# Mounted load validation (§10.2 / §13.8)

## Scope and authority

This is a **gate runner**, not certification of the current checkout. The only durable session/event authority is the target Host; Project Catalog owns project/workspace references, target WorktreeService owns worktree facts; the mounted Shell/ProjectSidebar/SessionPane owns only focus and drafts. The runner owns disposable fixture paths, schedules and measurements, never business state. Do not launch Desktop/Web with real HOME or userData. The runner requires a caller-supplied production driver module; no detached-tree/Button fixture or in-memory substitute may pass the mounted gate. No paid provider or SSH use.

```text
runner → disposable tiny Git repo → target Git discovery (read-only)
       → production Catalog/Host admission → synthetic Harness events → durable Host journal
       → actual mounted Shell/ProjectSidebar/SessionPane → browser interaction samples
       → owner counters + cleanup/reconnect facts → artifact manifest
```

Each session has unique command/turn identity. Send/admit once; detach only removes subscription. Reconnect queries/replays Host journal by cursor, never resends prompt. Host epoch and session identity fence late events. Desktop continuous and Web remote replayable are distinct delivery modes: record both separately; do not interpret connection interruption as session completion. No timeout-based sync: wait for explicit owner sequence/cursor. Fail if unknown, offline, or gaps are presented as caught-up. Counters come from owner calls, not DOM heuristics. A false observation or missing counter is a failure, not zero.

## Contract / fixture

`scripts/e2e/multi-harness/load/runner.mjs` exports `runLoad({driver, delivery, durationMs, eventCount, worktreeCount, sessionCount, expandedCount, reconnectEveryMs, sampleEveryMs, idleMs, artifactBase, baselinePath, sourceCheckout, buildArtifactPath, mode, isolateProcessEnv})`. Driver is loaded via `--driver <absolute .mjs>`; acceptance through the programmatic API requires `isolateProcessEnv:true`. The CLI strips inherited environment except a small process/locale whitelist and isolates HOME/XDG/data paths before importing the driver, then switches to the run-specific paths before `open`; acceptance through the programmatic API does the same before `open`. This does not grant permission to contact a live Provider; the driver must enforce no-network/no-account use. The smoke CLI requires explicit `--duration-ms` and `--events` (other scale flags: `--worktrees`, `--sessions`, `--expanded`, `--sample-every-ms`, `--reconnect-every-ms`, `--idle-ms`, `--max-backlog`, `--max-owned-children`). The runner does not import mutable product internals. A production driver must implement `dispose()` and `open({root,repo,worktrees,artifacts,isolation,mode,registerCleanup,registerChild})` returning:

- `mount({expandedWorktrees, sessions})`: create 10 distinct **synthetic runtime** sessions across ≥5 expanded workspaces through actual production Catalog/Host and mount the real Shell + ProjectSidebar + SessionPane. Return `{ mountedSurfaces: ['Shell','ProjectSidebar','SessionPane'], owner:'durable-host', delivery:'desktop-continuous'|'web-remote-replayable' }`; do not return this metadata unless independently verified. Acceptance additionally requires `mountEvidence:{shellVisible:true,sidebarVisible:true,paneVisible:true,hostJournalReopened:true}` verified through real mounted page selectors and read-after-reopen durable Host query; no Button/detached tree substitution.
- `discover({repo, candidates})`: read-only production target discovery; return stable candidate IDs (including main), no Agent start, no Git mutations. Worktrees passed to mount are the discovered real paths.
- `emit({sessionId, eventId})`: inject one synthetic Harness event into the **real durable Host**; resolve only after committed sequence. No paid Model calls.
- `sample({sessionId})`: perform a real typed-input + session-switch interaction on the mounted page, returning `{typedInputMs, sessionSwitchMs, focusStable, draftStable, selectedStable, worktreesStable}` measured from browser interaction to painted response (not RPC response).
- `detach()` / `reconnect()`: sever and restore client attachment, not Host. `reconnect()` must query the owner journal, return `{replayedWithoutResend:true, caughtUp:true}`.
- `facts()`: return `{durableEvents, backlog, backlogHighWater, implicitCliStarts, fullHistorySidebarReads, worktreeMutations, childProcesses, acceptedPrompts, focusStable, draftStable, selectedStable, heapBytes, rssBytes}` from instrumented owner + process metrics; all numeric fields finite nonnegative, booleans true. `backlog` is committed minus UI-consumed event sequence, not history row count. `backlogHighWater` is the owner-observed maximum between calls (not just the sampled maximum). Default bounds: backlog high-water ≤10,000 and at most 32 owned child processes at any point; configurable (`maxBacklog`, `maxOwnedChildren`) only with explicit comparable baseline/load documentation. Acceptance requires separate `processes.host` and `processes.renderer` `{heapBytes,rssBytes}` samples while mounted, both >0, and `processes.host` after cleanup/idle. Renderer may have exited after close. Never present runner heap as product heap; aggregate heap/RSS fields must explicitly represent measured product processes, not the fixture runner.
- `gatewayProbe?()`: optional local Fake Provider **pure ingress→executor→egress** adapter samples in milliseconds; no live Provider traffic. Omit if unavailable and mark unsupported.
- `close()`: explicitly close mounted client and synthetic sessions/children without terminating unrelated processes. Subsequent `facts()` must show zero owned child processes; idle memory samples must be taken after cleanup. Driver must not modify global account/config data.

All counters are run-scoped, not global history; all hooks must return truthful production instrumentation. No production driver is shipped at this checkpoint; a missing driver fails closed. Driver version + production commit + shell/Host provenance must be placed in `metadata` by `open` for review. For comparable runs, the runner independently reads `sourceCheckout` Git HEAD and hashes `buildArtifactPath`; these must remain available to recheck the baseline when running the candidate. Tests use a labeled **contract stub** solely to test runner invariants, never to claim mounted success.

## Gate, evidence and failures

Run `--delivery desktop-continuous` and `--delivery web-remote-replayable` as **separate** isolated acceptance runs with their own matching baselines; a single delivery result does not certify both paths. Defaults: ≥50 *real* worktree candidates from a newly initialized disposable tiny Git repo (never this project repo or any artifact base inside a Git checkout); 10 sessions in ≥5 expanded workspaces; ≥100,000 committed events; ≥8 hours elapsed monotonic clock and ≥60 seconds idle after cleanup. Attempts to call `--mode acceptance` with lower minimums fail before any Git/process launch. `--mode smoke` allows smaller duration/events, always reports `smoke` even if all counters pass. Every run creates a fresh temp directory; no cleanup of pre-existing directories. A rejected preflight (invalid mode/minima, absent driver, or artifact base inside checkout) must not create directories under the checkout; a run that passed preflight writes `result.json` even on gate failure. Driver exception messages are not copied into artifacts or stdout, only the failing gate phase. The output records a status (`smoke-only`, `failed`, `load-measured-baseline-pending`, or `load-measured`; never automatic product certification), reasons, elapsed, counts, owner-observed event backlog high-water/final, typed/switch p95, time-series heap/RSS (including post-idle/cleanup), process counts, provenance and unsupported checks. Acceptance samples must visit all ten sessions and be sufficient (≥20 each); no zero-latency defaults. Missing baseline means regression **unmeasured**, never ≤10%. Compare only preserved baseline worktree/commit on same machine and *same config/driver/load* with a different preserved baseline commit, separately for typed and switch p95; nonmatching baseline is rejected. The explicit runner regression budget is +10% per p95 and an over-budget run fails; agreeing on this budget does not certify the baseline or production. Separate Fake Provider adapter-only latency from live Provider compatibility (not measured here).

During setup: derive isolated HOME/XDG and Desktop userData and Web browser profile **inside the new artifact root**, prove realpaths are descendants before any driver launch; pass the paths into `open`; driver must attest the effective app/browser paths and must reject otherwise. No regular HOME, credentials, inherited provider keys, production server endpoints, SSH, or real accounts may be used. Driver must refuse to run if mount/runtime hooks are unavailable. Artifacts must not contain credentials, prompts or endpoint URLs.

Short contract tests: `mise exec -- node scripts/mise-run.mjs pnpm exec node --test scripts/e2e/multi-harness/load/*.test.mjs` (if pnpm dependencies absent, `mise exec -- node --test scripts/e2e/multi-harness/load/*.test.mjs` uses only Node/Git). Production gate command after mounted integration is stable and driver is implemented:

```sh
# In MAIN, from the integration checkout; run as a background job managed by MAIN, not a child agent.
# bg_run(command="mise exec -- node scripts/mise-run.mjs pnpm exec node scripts/e2e/multi-harness/load/runner.mjs --driver /ABSOLUTE/ISOLATED/production-driver.mjs --mode acceptance --delivery desktop-continuous --artifact-base /ABSOLUTE/DISPOSABLE/ARTIFACTS --baseline /ABSOLUTE/BASELINE/result.json --source-checkout /ABSOLUTE/PRESERVED/CANDIDATE/CHECKOUT --build-artifact /ABSOLUTE/PRESERVED/CANDIDATE/BUILD", timeout=32400)
```

Driver and baseline are required for production certification; the above is an invocation *template*, not a claim those files exist. Reserve an isolated hardware window; run preserved baseline and candidate serially under identical 50/10/5/100000/8h settings, then inspect both result.json files. Do not run a second broad build/browser load concurrently. Unavailable mounted driver, absent comparable baseline, or missing Desktop/Web isolation proof are explicit product gates, not skips declared green.

## Repair contract: partial-open ownership and latency comparison

Before calling `driver.open`, the runner owns a cleanup registry. The driver exposes a **top-level `dispose()`** that can be called even if `open` rejects (idempotent across `mount.close()` and partial launch). `open` receives `registerCleanup(fn)`; register a cleanup function *before* any asynchronous launch and invoke it once at teardown, last-in-first-out. Immediately after spawning each real child, call `registerChild(child)` before any await or fallible work. Even if `open` throws, the runner drains the cleanup registry, calls `dispose()`, and verifies all registered children have emitted `close` with a real exit; it signals a stranded registered child and marks the run failed rather than trusting a `childProcesses:0` report. Mount `close()` remains required on success. No unregistered child launch or fire-and-forget process is allowed. Cleanup failures are phase-only diagnostics (no stderr/secret output). Resource ownership order: runner registry established → driver registers disposer → child launch + immediate child registration → open/mount → close → registry drain + driver dispose → child close proof → post-idle facts. An absent mount on partial-open cannot supply owner counters; cleanup evidence reports only registered child exits, and the run fails.

Latency comparison is independent from the long-stress minimum. A preserved baseline source checkout must exist outside the artifact tree with clean tracked files, at a different Git HEAD from the candidate; the runner reads Git HEAD independently for **both** checkouts and matches each against the claimed commit, instead of trusting baseline JSON. Record/compare hardware fingerprint, delivery, fixture/load config, idle window, measurement window, driver version and independently hashed build artifact (a binary hash alone does not prove the binary was compiled from the claimed source; release certification also needs trusted build provenance). An explicit p95 budget of at most 10% applies separately to typed input and session switching; over-budget fails. A repeatable shorter baseline is valid only against a candidate latency run with the same controlled dataset, load and measurement window; both remain smoke/latency evidence, never an 8h stress result. Genuine candidate stress remains >=8h per delivery (not 32h as a single-run minimum), >=100k events and the stated fixture/session minima. Baseline source and artifact identity must remain preserved for independent audit; no auto-adoption of rebuilt same-path source. Missing provenance or inconsistent claims are incomparable and not certified.
