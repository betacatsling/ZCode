# External session V4 projection (incremental implementation contract)

The target host alone persists canonical events. Projection is a deterministic read model rebuilt from a contiguous, de-duplicated epoch journal; it never sends commands or executes tools. A `message.finished` replaces earlier deltas for the same message ID. Tool input is displayed as uncommitted text until a structured terminal tool event proves a complete value. A pending approval is displayed only after the adapter has installed a real execution-blocking gate, and is removed on the matching resolution/turn completion. A new turn must not inherit a previous turn's interaction. Unknown/unsupported actions are server-rejected as well as disabled in UI.

Host read model: the event journal remains the sole transcript authority. A writer publishes a durable committed byte cursor only after fsync of the event line. Read-only replay uses exactly that committed prefix; an incomplete trailing write cannot appear as an event. A stale extra suffix after a writer crash is execution-unknown and requires inspection before attaching. Legacy journals without a cursor are readable only when their complete newline-terminated content validates; a writer establishes a cursor before admitting new appends. Rows pagination projects one consistent event view for rows and seq/revision, uses numeric monotonic row IDs, and can reach every older row without a 100,000-row cutoff.

The per-session lightweight activity summary is a versioned, atomically replaced projection of the event/command journals, not an independent admission store. Event cursor and command revision are checked on every cold read; a mismatched, missing or invalid summary is rebuilt from contiguous journals once, under bounded independent read operations, never silently interpreted as idle. New command admission/finish and event append are durable before publishing the derived summary. Until the summary catches up, unknown means uncertain for maintenance; mounted Host state remains authoritative. A completed turn and terminal, acknowledged command may become idle only after all pending tools/interactions are resolved; a pending accepted send is running while mounted and uncertain after restart. Creating/reserved sessions are uncertain. `getSessionReadModel(spec)` provides a read-only DTO `{runtimeEpoch,seq,activity,lastOutcome?}` for later sidebar/lifecycle composition without starting an adapter; creating or unreadable records return uncertain (unknown epoch/seq where unprovable). Unread observation belongs to the observing client, not the Host and is not inferred from timestamps.

```text
single Host writer: command accept → fsync command → summary revision; event append → fsync event → committed cursor → summary(seq,epoch); command finish → fsync command → summary revision
cold reader: manifest + cursor/revision → matching summary OR one contiguous rebuild → activity; mismatch/corruption → uncertain (never idle)
rows reader: one committed journal view → projection(rows,seq,revision) → requested bounded page
```

The native V4 transport and native projection remain unchanged. External snapshots use additive `agentHost` metadata and stable `logEpoch`/`seq`, expose a bounded `rows.window`, and paginate older rows from host records. Canonical event replay must not prompt, approve or write files. UI streaming and resync use the same authoritative journal cursor, never a renderer-owned transcript. First integration covers text, tools, approval, usage and control; richer rows are gated by separately certified capabilities.
