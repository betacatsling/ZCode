# Canonical semantic events (additive v1)

Owner: target Host journals commands and adapter events; projector derives V4 snapshots only. Adapter owns native question gate and visible text extraction; Model bridge owns private signed reasoning, never the canonical journal. Native V4 remains its own owner. Existing journal records retain their original shapes and read without migration.

Events: reasoning.started/delta/finished identify a visible reasoning item (terminal replaces deltas). No signatures, redactedData, metadata, raw request payloads or credentials in this lane. Structured plan.updated uses `items` (id/content/status) instead of legacy `text`; subagent.updated retains original child identity, optionally source harness/type and parent tool, never claims a native V4 child conversation exists. Question interaction uses a discriminated `interaction.requested` variant with prompt/freeText/options and optional tool anchor; permission is unchanged. Answers use `answerInteraction` with nonempty answer and no permission decision; optional adapter method returns structured unsupported when absent. Permission resolution never accepts an answer as approval. Capability `questions` is optional and absent/unknown is not support.

Usage v1 without `accounting` remains legacy delta per event. New usage specifies `accounting: delta | absolute` and stable `sourceId` (one Model call), `inputTokens`/`outputTokens` represent *uncached* input/output when cache is supplied; cacheRead/cacheWrite are separate, reasoningTokens optional, and source re-report replaces the prior snapshot for absolute. No mixing a source's delta and absolute values; missing metrics stay absent in canonical records, V4 mandatory counters present zero for display only. Pi SDK message usage is per assistant message, not cumulative per session; input excludes cacheRead/cacheWrite (Pi API fields). Each message's ID is the source; explicit delta once per message. No double count if re-delivered.

Order: UI stable command ID → Host journal accept (durable) → verify epoch, active turn, pending interaction, capability → adapter answer → native resolved event → Host journal append and summary → projection. Duplicate command returns original receipt; stale answer is rejected before adapter. A gap/collision fails closed. On crash after adapter delivery without confirmation receipt is execution-unknown, not retried. Desktop continuous and mobile replayable both read the same committed journal; snapshots/older pages do not replay prompts. Unknown extension events are bounded, versioned inert data; legacy extension JSON remains read-only parseable, while new extensions persist only the inert marker `unsupported` until a separately reviewed sanitizer exists. Future schema versions fail closed.

Acceptance: mixed text/reasoning/tool/structured plan/child/question/usage transcript, terminal replacement, dedup, stale reply, committed-prefix older page over 100k, Pi SDK fake Model producer; provider live tests gated.
