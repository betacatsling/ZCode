# Target runtime lifetime (P4 bounded seam)

Target owner is the existing standalone ZCode Server Supervisor (one data-root lock), whose Core owns Host services and journals. Window Local Host and SSH are attachments, not process parents. Installation UUID is the stable target identity; port and Core generation are ephemeral. An attachment must validate `/api/server-info` identity and protocol, obtain the one-use `/ws/host` ticket, and only then open the trusted WebSocket. A mismatch must fail closed; never reissue an accepted prompt on reconnect. Host journal/command receipts are the only replay/admission authority.

```text
GUI/SSH connection -> target supervisor lock -> Core generation -> Host owner/journal
             detach  -X-> supervisor/Core; accepted commands continue
Core exit -> supervisor crash budget -> new Core generation -> reattach/history
explicit stop/update/uninstall -> guard native + external activity -> Core exit
```

Native activity is counted by lifecycle telemetry; external activity must come from target Host `getRuntimeActivity()` (`running`, `waiting`, `uncertain`). Waiting approvals and uncertain recovery are unsafe. A missing/failing activity source or a Core crash is _uncertain_, not idle. Core is queried for fresh activity during update/uninstall admission rather than using only a periodic heartbeat; integration must fence **new** Host admission through Core shutdown because a count query alone is not atomic with a newly accepted command. Read-only status can expose native counts and external uncertainty independently; update and uninstall reject unsafe activity unless update is explicitly forced. Explicit operator `stop`/`restart` remain distinct intentional actions (and must leave interrupted/uncertain journal state rather than fabricate completion); crash-budget restart occurs only after the old Core has exited. Fallback-to-service migration and automatic maintenance reject unsafe activity; startup-failure cleanup may forcibly stop the partial Core, but no GUI close/SSH detach calls it. In-flight update/uninstall serializes via the existing Supervisor lifecycle operation gate. The Core does not own a second task store or model process. Core stdout/stderr are permanently drained by its supervisor (`ignore`); actual agent output is journaled by Host, independent of a connected window.

macOS: `invokeUserOwnedServer({node,cli,serverRoot}, "serve" | "status" | "stop")` in `desktop/src/main/targetServerProcess.ts` invokes the packaged standalone CLI `serve --daemon --server-root <owned-root> --json` with `ZCODE_SERVER_SKIP_SERVICE_REGISTRATION=1` (existing detached fallback, no global service registration). Paths must be absolute; integration supplies an owned root and packaged runtime/node path, not dev-time source. `status` is read-only, `stop` explicit. Linux: provision the **same packaged CLI** under a user-owned SSH target root, start with the same opt-out via short-lived SSH exec, then open an authenticated SSH loopback forward to the Core's current port. Neither `IRemoteBackend.exec()` nor the tunnel owns the daemon. On reconnect query the target Supervisor's `status --json` through authenticated SSH; never reuse an old Core port.

Attachment API: `prepareTargetAttachment(loopbackEndpoint, expectedInstallationId, readInfo?, expectedVersion?)` in `services/src/agent-host-lifetime/targetHandshake.ts` returns `{serverId,websocketUrl,ticket,expiresAt}`; `openTargetHostSocket(ticket)` in `desktop/src/main/targetServerAttachment.ts` performs the one-use trusted upgrade and returns a WebSocket. Integration must expose the handshake through a public service entry, provide authenticated SSH transport and the target root, and connect that socket to the existing RPC channel client. Mount/unmount must not create/stop a target worker. `serverId` is the validated installation UUID, never a port/path/SSH session. For a new install obtain the installation ID over authenticated target control; do not discover it from an untrusted forwarded port. Remote credential durability remains a release gate.

Acceptance: fixture child Core survives client disconnect while continuing output; a fresh read blocks a waiting approval despite an old idle heartbeat; one-use ticket replay and protocol/version/identity mismatch reject; crash yields uncertainty. Real Host command replay/no duplicate prompt, a child losing Supervisor IPC, packaged GUI and SSH E2E remain integration/release gates.
