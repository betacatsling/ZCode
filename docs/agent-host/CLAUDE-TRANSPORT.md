# Claude Code raw Agent SDK transport (2.1.263)

Foundation only: no HarnessAdapter registration, host-managed model certification, GUI or remote process lifecycle. Pin `@anthropic-ai/claude-agent-sdk@0.3.263` (package metadata `claudeCodeVersion: 2.1.263`); the bundled CLI is used. Do not substitute `@anthropic-ai/sdk` (model API client). The caller owns host/turn identity, command admission, Gateway authorization and journaling; this transport owns one child process/turn, native session ID, pending tool decisions and bounded native events. Claude owns native conversation and tool execution.

```text
caller send -> SDK query (isolated child argv/env) -> native events -> caller
native PreToolUse -> pending (toolUseID + session + turn) -> caller decision
  -> SDK hook allow/deny -> Claude executes or rejects tool
caller cancel -> abort SDK query -> clear pending -> late decision rejected
```

The bounded native Messages profile requests disabling experimental beta headers/tool-schema additions through the documented launch environment `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`, not by editing outgoing requests. Pinned CLI 2.1.263 still emits three beta markers (`claude-code-20250219`, `effort-2025-11-24`, `interleaved-thinking-2025-05-14`), so this is not a certified native Gateway profile. The profile deliberately does not support dependent MCP tool search; the SDK process receives this flag in its isolated env. The Gateway remains the admission owner and rejects any remaining unsupported beta or field. Verify the exact pinned CLI's emitted requests before treating the profile as compatible; do not infer compatibility from SDK option names.

SDK `PreToolUse` hook is mandatory for **every** tool, including auto-allowed calls which bypass `canUseTool`. Its decision is the actual pre-execution gate; `canUseTool` is separately fail-closed for any additional permission request and must not be treated as universal. A hook without a matched active turn/decision denies. No timeout converts a missing decision to allow. Duplicate/late decisions fail closed. The SDK starts only with explicitly supplied absolute `cwd`, profile outside the workspace and personal HOME, isolated `HOME`/`CLAUDE_CONFIG_DIR`, injected session-scoped loopback Messages URL and token; never copy parent authentication/provider environment. `settingSources: []`, `strictMcpConfig`, explicit `tools` and no plugins disable implicit repository settings/MCP (no `--bare`: it disables hooks). SDK 0.3.263 officially exposes `thinking: { type: 'disabled' }`; select it explicitly for the bounded no-reasoning trial, without manually stripping request fields or beta headers. This setting alone is not proof that context management, cache directives, metadata, effort or SDK auxiliary endpoints disappear; retain 422 admission until the actual emitted body proves compatibility. Only `--resume` with the opaque recorded native ID and same isolated profile is permitted; do not infer success of resume until a native init frame confirms identity. No shared process and no tool-approval state beyond a turn. Unsupported fork, detach, mode switch, unsolicited controls are explicit unsupported.

Expose bounded structured init/session ID, text delta, complete tool call, tool result, permission request and terminal result/error. Never parse TUI or stderr for state. Validate native `claude_code_version` against the pinned CLI on init. Enforce post-SDK-parse per-event byte bounds, total event and pending approval bounds; oversize events abort. The SDK owns raw line framing and its own pre-parse limits; this transport cannot independently limit bytes before the SDK parser. The SDK manages line framing; the injected process spawner records exit status independently. Both successful native `result` and zero process exit are required for success; a successful result followed by nonzero exit is failure. Abort/exit/protocol failure clears pending approvals and rejects stale replies; no stdout/stderr/secrets leak in errors. Native usage is metadata, never fabricated cost. Host event ordering/replay belongs to Host, not this transport.

Acceptance: deterministic synthetic SDK frames, approval wait/deny, late reply, bounds, result/exit mismatch, cancel; actual isolated fixed SDK + bundled CLI fake local Messages endpoint must show pre-execution Edit denial with unchanged file, and delayed approval cannot execute after cancellation. Synthetic ingress is not a live Provider or multi-turn model certification. No account/network upstream calls. Lockfile is owned by integration lane; exact dependency needs resolution there before clean install/typecheck.
