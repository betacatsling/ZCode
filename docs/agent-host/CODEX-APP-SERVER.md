# Codex app-server adapter scope

Pin CLI 0.156.1; communicate using its documented JSON-RPC app-server over stdio, not TUI scraping. At create, use an isolated `CODEX_HOME` and a session-scoped custom `model_provider` pointing only at the target-local Gateway; do not write global `~/.codex/config.toml` or pass credentials in command arguments. `thread/start`, `turn/start`, `turn/interrupt`, `thread/resume`, item and turn notifications, usage, and server-initiated command/file approval are distinct control surfaces. An approval callback must retain the exact RPC request ID until the target host durably accepts the matching response. Unrecognized requests never auto-approve. The adapter version and CLI version must match; an upgrade returns history-only until fixture revalidation.

On 2026-09-24, an isolated `codex-cli 0.156.1` probe (`ZCODE_CODEX_PROBE=1 node packages/services/test/fixtures/probeCodexAppServer.mjs`) completed initialize → thread/start → turn/start, then sent `POST /v1/responses` with `client_metadata`, `include`, `input`, `instructions`, `model`, `parallel_tool_calls`, `prompt_cache_key`, `reasoning`, `store`, `stream`, `tool_choice`, `tools` and `stream:true`. By default the fake Gateway intentionally replied 400, yielding a structured `error` notification. With `ZCODE_CODEX_PROBE_FAKE_SSE=1` it emitted a synthetic text Response and the CLI emitted `item/completed`, `thread/tokenUsage/updated`, and `turn/completed` (status `completed`). `ZCODE_CODEX_PROBE_NO_REASONING=1` set request effort to `none` but Codex still included `reasoning.encrypted_content`. These are isolated control/protocol observations, **not** real Provider or model-route certification. Before claiming host-managed support, record the actual Responses HTTP paths, fields and auxiliary calls made by this pinned version against a synthetic local Gateway. A local protocol probe may use a fake provider and isolated worktree without actual credentials, but does **not** establish model quality or Provider identity. The Gateway must preserve tool-call/result pairing, system/developer instruction hierarchy, structured errors, streaming deltas, cancellation and usage; unsupported features must reject the turn before any side effects, not silently drop them.
