# Profile Project Catalog (P2)

The Profile Project Catalog is the single durable writer for project display metadata, order, workspace references and view preferences. It is independent of open tabs and never owns Git identity or session runtime state. The injected target port alone inspects repositories, discovers unadopted candidates and creates/adopts/removes verified workspaces. The Catalog persists the returned target facts; a remote/offline failure never becomes an empty discovery or local fallback. Target and generation are part of each identity; matching paths on different targets must not merge.

```
request → one profile owner (exclusive lock) → target port → atomic catalog commit → revision/change notification
complete Host session index → pure summary derivation → sidebar snapshot; no focus/Agent commands
```

Opening a second owner fails. Lock recovery is explicit after a crash (not automatic lock stealing): a stale writer must never commit after another owner takes over. Catalog writes are atomic and schema-versioned; unknown future versions reject mutation, not silently reset. A failed target operation leaves catalog unchanged. If target creation succeeds but catalog commit fails, the target's next read-only discovery exposes the unregistered candidate for recovery; never delete its files as compensation. Profile mutation is serialized. Project hide and workspace hide are view preferences. Archive/unarchive is a target admission policy change, not Git delete, stop or branch deletion: profile owner serializes it with its metadata write; target persists deny before publishing archived metadata, and publishes allow only after unarchived metadata is durable, under the same target admission gate used for create/send. If either side fails, target denial wins; a restart must reconcile profile archive flags with target policy before accepting admission. Offline target fails closed, never reports local-only archive success. No existing tasks are cancelled. Removal is a distinct target-confirmed operation. Ordering is explicit and stable across summary updates.

The concrete target bridge registers persistent target binding→project ownership and converts target worktree records into catalog DTOs; it never trusts caller-supplied execution facts. Removal sends the Catalog's stored workspace DTO by value across RPC and checks it against the target record; no target-local lookup callback crosses process boundaries. Dedup probes actual target-local common-directory instance evidence/marker, not the common-directory path: a rebuilt repository at the same path must be a new binding. Linked paths of the same instance dedup. Remote identity is supplied by an injected trusted target identity resolver using the shared identity format; local identity is canonical path. Host admission checks persisted catalog project/binding/workspace ownership and identity before the target gate verifies generation/canonical cwd and keeps that gate through the Host callback. Only a serializable DTO crosses RPC; the Host callback remains process-local. Removal preview is read-only and returns dirty, untracked, submodule, Git lock, main, runtime activity and unknown/offline flags; explicit confirmation is valid only after a preview for that generation and is rechecked under a frozen gate before non-force removal. Scan failures preserve last-known records and report unknown freshness, not an empty tree. The Catalog RPC contract exposes asynchronous snapshots/revision and a change Event; registration/mount is separate and must not create a second catalog owner.

The session index provider supplies the complete top-level session summaries, including hidden workspaces, archived records and unopened tabs. Catalog never opens transcript bodies or launches agents to compute counts. Archived sessions do not count; stale/offline is a separate workspace freshness dimension, not proof a turn has stopped. Waiting/error attention remains reachable even for hidden workspaces. Revision notifications follow durable writes or trusted Host index change events; a failed Catalog write emits no Catalog change. The snapshot carries an owner-epoch-monotonic revision (clients refresh after reconnect). UI focus is outside this contract.

Migration consumes `LegacyPersistentSessionIndexReader`, implemented by the **native persistent session owner**, never tabStore or a synthetic JSON approximation. `exportAll()` must return a consistent, complete (closed tabs included) export with source schema version, stable profile ID, revision and checksum. For the current SQLite `tasks` index the adapter must export `workspace_key` (identity isolation), `workspace_path`, `task_id`, native `meta_json`/model selection and original cwd; Identity matching uses `workspaceIdentity?.trim() || workspacePath` for legacy local path fallback, always scoped to the verified target; if model binding, target identity, Harness or subdirectory cwd cannot be recovered authoritatively, leave the record pending rather than inventing a default. SQLite backup uses its owner's consistent backup mechanism (not a live WAL main-file copy), and must certify the _same_ profile/revision/checksum. Dry-run performs target verification without Git mutation and returns pending for offline/unknown/non-Git/ambiguous records. Apply requires the verified backup and rechecks source revision before atomically publishing a versioned mapping sidecar; native ID, model binding and subdirectory cwd are copied losslessly, not regenerated. Re-running is idempotent by stable legacy ID. Failed verification leaves pending records readable and does not partially publish mappings. Future-version sidecars reject writes. Rollback verifies the backup and removes the sidecar without changing native history. **The concrete native SQLite reader/backup adapter and Runtime consumption of these mappings are separate unaccepted integration seams.**

Composition seam (not mounted in `node.ts`):

```text
profile owner: ProjectCatalog.open(profileCatalogFile, targetRpc, completeSessionIndex)
                                     │ serializable ProjectCatalogTargetPort DTOs
                                     ▼
target owner: TargetWorktreeService.open({storageDirectory, executionTargetId,
                                         activity: aggregateNativeAndExternalActivity})
              └── ProjectCatalogTargetBridge(target, targetId,
                    (targetId, canonicalPath) => trustedIdentityResolver(targetId, canonicalPath))
Host create/send → CatalogWorkspaceAdmission(catalog, target, targetId)
                   .withAdmission(specV2, async canonicalCwd => Host durable command admission)
archive → target persistent deny → Catalog metadata commit → Event revision
unarchive → Catalog metadata commit → target persistent allow → Event revision
remove → catalog.previewRemoval → target gate+Git/activity facts → confirmation
          → target freeze+recheck+non-force Git remove → Catalog commit
```

The composition owner must supply a trusted remote target descriptor to `buildRemoteWorkspaceIdentity` (shared helper), using canonical worktree path; for local it supplies the canonical path. It must inject complete native+external activity and route target calls through an actual RPC transport. This file deliberately does not register a global channel or mount the Host. `IProjectCatalogRpcService` and `IProjectCatalogTargetRpcService` are descriptor-ready names, not registered endpoints. Target `withAdmission` accepts the Host callback only inside the target process; a remote Host must expose a target-local Host command boundary rather than sending callbacks over RPC. No production call path is claimed until that boundary is mounted. A failed Catalog commit after target registration retains the target record for explicit recovery. Profile/archive and target/archive can diverge on a failed write; denial wins and operator reconciliation is required before allowing new commands.

Acceptance: empty durable project, restart and competing owners; target-scoped same-path identities; snapshot complete counts and hidden waiting attention; no focus commands; migration dry-run/backup/idempotent retry/pending/future-version rejection; duplicate summary arrays rejected by shared parser.
