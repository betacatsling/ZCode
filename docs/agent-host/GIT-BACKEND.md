# Target-local Git worktree backend (foundation)

This adapter reads Git facts on the *execution target* only. Its caller supplies a local path on that target; routing, target identity, durable workspace IDs/generations, catalog state and admission belong to the future WorktreeService. No discovery operation starts an agent, runs hooks, repairs, or prunes a repository. Non-Git directories and Git installations without `worktree list --porcelain -z` fail explicitly; a failed scan never means an empty list.

`discoverGitWorktrees(cwd)` resolves Git's actual nearest repository (including a linked `.git` file, submodules, and nested repositories), returns its absolute common directory, the current worktree root if non-bare, and records from Git's NUL-delimited list. Bare repositories have no runnable main cwd. Each record has `main`, `linked`, or `bare`, branch or detached HEAD, and optional locked/prunable reasons; paths are facts, not stable identities. A cwd under a different nested repository must be separately discovered, not assigned by path-prefix matching. `resolveGitWorktreeCwd(root, cwd)` rejects symlink escapes by realpath and preserves a valid descendant cwd rather than changing it to root; it does not identify a target or check admission.

`createGitWorktree({repositoryPath, path, branch, mode, baseRef?})` requires an explicit existing/new branch mode. It checks literal branch syntax and existence, commit ref for new branches, existing canonical destination parent and destination nonexistence, and known repository/worktree Git lock files, and refuses already-checked-out branches. Git is invoked by argv with no force/overwrite; the backend does not delete a failed destination or branch. Creation may race external Git operations; a failure is reported unchanged to the caller for reconciliation. Controlled mutation disables repository hooks. It never `git init`s, clones, prunes, or deletes a branch.

`preflightRemoveGitWorktree(repositoryPath, path)` returns risk facts: tracked changes, untracked or ignored files (both treated as removal risk), submodule entries, lock/prunable status, main/bare status and known Git lock files. `removeGitWorktree(repositoryPath, path)` rechecks these facts immediately before a non-force Git remove and refuses any risk or unmatched path. The caller must first obtain confirmation, freeze new-session admission, stop/reconcile active sessions and unknown/offline owners, then recheck. Git facts alone **never** establish safe removal: external writers can race this check. A removed linked worktree retains its branch and history. No arbitrary filesystem `rm` is used.

Event order: caller target routing → read-only Git discovery → explicit create OR (preflight → caller freeze/stop/confirmation → recheck → Git remove) → caller catalog update. The caller owns synchronization, idempotency, stale-result rejection and desktop/mobile delivery; this backend has no persisted state. Tests use disposable local repositories, not live SSH or existing user repositories.
