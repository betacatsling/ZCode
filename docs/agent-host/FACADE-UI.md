# V4 external conversation facade (bounded transport seam)

Native sessions remain owned by the existing ZCode V4 runtime. Target IAgentHostService owns external session specs, durable create reservations/command receipts, canonical journal, and projected snapshots/rows. Renderer holds only scoped owner metadata, subscription IDs, ACK activation buffers and pending drafts; it does not project AgentEvent into business rows, execute tools, or persist history. Feature-off returns the _same_ native transport; disabling new external admission does not hide existing external history.

Owner lookup is explicit and scoped: known native ID or externally owned `(targetId,workspaceId,hostSessionId)` with stored SessionSpecV2. Unknown ID fails closed; backend-native session IDs are never UI keys. New create carries `payload.agentHost.spec` (target-verified by Host), preallocated hostSessionId, and stable commandId. The legacy V4 `payload.workspaceId` is **not** interpreted as a WorktreeWorkspace.id: stable workspaceId is supplied in spec and Host verifies target/worktree membership. Creation uses only Host `create(spec,commandId)`; ambiguous ACK recovery uses Host `queryCreationCommand(commandId)` and native query, rejecting conflicting claims. Unsupported first-input attachments/config and advanced V4 operations reject rather than pretending support. A host accepted receipt maps to accepted ACK, not turn completion. An execution-unknown receipt is a failed ACK with an explicit `execution-unknown` reason, never a definite rejection. Send uses commandId as turnId and dispatches once; unknown execution is not retried. Stop requires expectedForegroundExecutionId and current runtimeEpoch; approval requires matching pending permission interaction, turnId and epoch. Detach is unsubscribe only, not terminate.

```text
UI → scoped owner lookup → Host create/dispatch (durable admission) → Host journal → projected snapshot
subscription ACK → activation → snapshot / subsequent snapshot frames (Host epoch+seq)
                       gap / epoch shift → eventsSince + authoritative snapshot (never resend command)
desktop continuous ──────────────────────────┐
mobile replayable ── snapshot + gap repair ──┴─ same Host seq and epoch
```

Each subscription has its own activation ID, topic and last `(logEpoch,seq)`. ACK-preceding notifications are buffered until activation; pre-activation events mark the subscription dirty rather than staging one full transcript for every token. Duplicate/late frames are ignored; gaps, epoch changes and stale owner results require an authoritative snapshot. A burst of Host events triggers at most one in-flight snapshot read per subscription and one follow-up when an event races that read. The latest authoritative snapshot replaces prior text (including final text), never appends to it. Desktop continuous and mobile replayable both receive the same epoch/sequence-authoritative snapshot; mobile gap repair uses Host history and never resends a command. No renderer-generated delta or local shadow transcript. Rows pagination delegates to Host rowsRange, preserving its cursor and epoch. Resync never dispatches a prompt. Client disconnect drops listeners only.

This is a bounded transport component, not the mounted pane: the production mount must supply an asynchronous resolver backed by the trusted native session index and Host stored spec/legacy index, and pass the actual service port (`create(specV2, commandId)`, global `queryCreationCommand(commandId)`, `snapshot`, `eventsSince`, `rowsRange`, `getSessionSpec`) without a cast. Until that API is published and the native sidecar resolver exists, no first-party create flow is connected. Native legacy sessions are not migrated or written by this seam; missing/future owner records cannot be guessed from path.

Acceptance: native off identity and on routing; both create-query buckets with native clock and ambiguous ID rejection; simultaneous subscriptions/activation, event duplicate/gap/epoch repair and independent sessions; unknown ownership rejection; detaching without terminate; unsupported capability guards and rows pagination. SessionPane create/header/actions and pane registry mounting remain owned by dedicated integration/mount work, not certified by this seam.
