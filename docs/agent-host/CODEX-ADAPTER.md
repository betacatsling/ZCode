# Codex pinned Host adapter — bounded support

Owner: target-local Codex adapter owns native process/thread, per-turn Gateway lease, approval callback association and ordered canonical event sequence. Host owns command admission, durable journal, workspace verification, model selection and persisted backend binding; Gateway owns credential authorization and immutable captured Model. UI never supplies an executable or Gateway token.

Trust: only manifest `{schemaVersion:1,id:'codex',name:'Codex',adapterVersion:'0.156.1'}` may be registered by target composition. Probe exact `codex-cli 0.156.1` on the actual target. No native-account fallback. Host-managed Responses with explicit reasoning `off` only; a high binding is unsupported before effect. Other tools/features not tested are not advertised. The pinned CLI still injects developer skills/permissions; Gateway must preserve roles. No paid Provider call is part of this certification.

Each admitted turn obtains a newly issued lease for its Host turnId and runtimeEpoch from the target-local issuer (captured exact Model, unique alias, bounded limits). Host `prepareTurn` freezes the exact per-turn plan before `send`; adapter cannot replan after Host admission. The session selection stays pinned unless a future Host contract changes it. Never use mutable global model selection or a caller-provided Model override. The adapter starts a _new_ isolated app-server process with that token and resumes the prior native thread ID using the same private profile after the first turn. On completion/interrupt/error revoke token and close the process before another send; no prompt replay. Never edit the token in a running child or reuse a previous turn token. If resume fails, mark execution unknown rather than creating a new thread. Late notifications/callbacks from an obsolete child may not advance the next turn. A token must be revoked even when launch fails. `thread/start` creates context once, `thread/resume` retains context; a fake SSE exchange alone does not prove context quality.

```
Host accepted send → lease(turn, epoch, frozen Model) → spawn pinned child → native start/resume → turn/start
native approval → canonical interaction.requested → Host durable decision → native reply
native completed/interrupt/error → revoke token → child close → next turn may lease/restart/resume
```

Canonical text/tool/interaction/usage/finish events are sequenced within the adapter and validated by Host journal. Native thread/turn IDs are not Host IDs. Unknown or late approvals decline. Cancel races must not turn a subsequent turn into success. On restart after process death, Host uncertain command rules win: no automatic resend of accepted turns. If native history cannot be verified, adapter attach refuses execution. History-only remains readable through Host journal.

Pinned Codex `thread/tokenUsage/updated.params.tokenUsage.last` is the latest native-turn usage snapshot, not a delta; ignore thread-wide `total` for per-turn accounting. Absolute snapshots may first omit unknown counters and later introduce them, but once a counter is known for the same `(turnId, sourceId)`, every subsequent snapshot must repeat it without decreasing it; omission is invalid, not zero. Host owns the committed usage ledger/journal; Codex adapter must reject its invalid native replacement before handing it to Host, including an empty replacement after a known metric. This guards the Codex input path, not generic Host journal atomicity for other adapters (reported separately). Negative/noninteger counters are malformed native input and must fail closed at transport/adapter before any Host usage append. Test-origin matched native notifications in a real pinned child/Host join must distinguish these paths, verify bounded unknown and single lease revoke/child reap after invalid input, independently reopen readable durable history and reject retries without another fake-upstream request. A stale or uncorrelated frame does not exercise this acceptance. Only project a snapshot with explicit matching `params.turnId` after the adapter has matched the native turn. Give each Host turn a stable usage `sourceId` and mark snapshots `accounting: absolute`, so repeated native updates replace that turn's prior counters instead of summing snapshots. Emit only counters actually reported (including explicit zero); omitted metrics stay absent. Host selection is immutable for the session: a changed `SessionSpecV2` on reopen refuses before lease issue or native spawn. Actual pinned-CLI tests exercise these rules through `SessionHost`, not only direct adapter calls.

Acceptance: fake child validates distinct per-turn tokens and scope, late-request rejection, approval denial, cancellation, and resumed-thread continuity without prompt replay; it does not prove user-facing model switching. The opt-in pinned-CLI Host/Gateway/fake-upstream join runs two turns on the same immutable Host selection, checks that the prior per-turn token is unauthorized, verifies source-scoped usage totals and refuses a changed model spec on Host reopen before issuing a lease or spawning a child. `agentHostCodexNativeControls.test.ts` separately exercises actual native denial/allowance/cancellation/reopen, while `codexGatewayJoin.test.ts` exercises native command denial and cancellation at the transport/Gateway seam. Per-turn aliases supplied directly to the adapter are not evidence that the current Host contract supports a user Model switch. This adapter is not registered into production composition in this lane. Desktop/mobile projections share the same Host sequence; desktop continuous and mobile replayable delivery are Host responsibilities, not parallel adapter queues.

## Protocol V2 closure (target Host contract)

New writes accept only `SessionSpecV2`; persisted V1 remains readable only through Host migration. Host verifies target/workspace/generation and realpath containment before create; Codex binding and lease must match that verified V2 scope. The adapter returns a V2 backend binding and refuses attach when its target/workspace/generation/harness/epoch differ. The native process cwd uses the verified `cwdRelativeToWorktree`, never an unverified caller path. Host owns journal admission; adapter owns native turn ID and per-turn lease.

```text
Host verified V2 spec → adapter V2 binding → frozen turn lease → isolated native process
native turn/start ACK → matched native turn events → matched terminal → revoke lease + close
unknown/interrupt failure → uncertain Host terminal; never infer success from a thread-only frame
```

Before the native start response, notifications cannot establish ownership by thread alone. Only an event carrying the returned native turn ID may project into the Host turn, including item/text/tool/usage and approval. A bounded pre-ACK queue may hold matching candidates but must discard other IDs and fail closed on overflow. Tests exercise V2 create/attach/subdir/stale scope, pre/post-ACK old events, delayed completion, cancel unknown and Host replay.

The isolated direct adapter fixture tests separate per-turn lease credentials and native-thread resume; the V2 Host native fixture retains its immutable first selection across turns, rejects a changed model spec on reopen, and verifies scoped usage accounting. These are distinct proofs; the direct adapter seam is not a user-facing model-switch capability.

## Durable native ownership (adapter-local, V2 only)

The adapter persists a binding/spec/canonical-cwd-scoped provenance record **before** acknowledging create, independent of the Host journal. `never-started` is written exclusively for a fresh, empty profile. Before spawning the first native child (and before `thread/start` or input), transition durably to `starting`; a crash here is ambiguous, not recoverable by creating another thread. After a valid native thread ID has been durably recorded with its `.thread` marker, transition to `established` before `turn/start`. On attach, require BOTH an exact record and matching marker for established sessions; never derive never-started from Host sequence (session-created events precede first turn). Missing, corrupt, legacy, mismatched or `starting` records refuse execution even if Host history exists. Host snapshot/history remains read-only accessible; a pinned CLI Host join first proves normal established reopen, then removes the native marker and proves reopened execution fails while the committed Host snapshot still reads. Established attach resumes exactly that native ID; a native resume failure is unknown, never a fresh `thread/start`. Reject unexpected marker on never-started attach. Atomic replacement and file/directory sync bracket acknowledgement and transitions. The profile is target-local, not a second Host journal; it never stores prompts or approvals.

```text
Host owns journal/admission → adapter record never-started → Host create receipt
Host accepted send → adapter record starting → child / thread/start
native thread ID → durable marker + established record → turn/start → matched native events
restart → exact record + marker → thread/resume ONLY; unknown → history-only
```

Early notifications/completions are bounded by both count (128 each) and encoded bytes (1 MiB aggregate per turn); overflow closes the native transport and makes execution unknown. Real Git/catalog admission must refuse foreign target, identity, path, generation, cwd escape and stale epoch before issuing a native lease; a pinned-CLI subdirectory run checks canonical cwd separately, not proof that a direct adapter test uses Git admission. Transport stdout has a 1 MiB encoded frame ceiling, including after a complete line and an unterminated tail in one chunk. Frames lacking explicit turn identity are omitted; the bound is not proof of complete native usage. Tests include missing whole profile, missing marker after committed history, fresh draft reopen, starting state and normal established reopen without prompt replay.

## Post-restart execution and transport death regression

An independent Host/adapter reopen with exact established provenance must execute the next admitted input on the **original native thread**, not merely return a saved snapshot: observe pinned CLI `thread/resume` with the durable ID, prior context in the next fake-upstream request, one new request, and no `thread/start` or duplicate prompt. After a native child dies during an admitted send, adapter owns unknown execution regardless of whether the transport rejects before or after `turn/start` ACK. Report `execution unknown` to Host, finish/revoke once, and never retry the accepted input automatically. Pre-admission validation errors remain validation errors; Host history stays readable after context loss.

A fresh `create` must claim a previously nonexistent private profile. An existing profile (even if its durable record is `never-started`, empty, or orphaned by a lost Host create receipt) is ambiguous for a _new binding_; it cannot overwrite the old record. Exclusive directory `EEXIST` is reported as native ownership unknown while preserving the original record and marker. An existing Host binding instead uses `attach` and exact provenance validation. Refuse replacement create before any native IO.

Acceptance for uncertain execution: V2 Host accepts send, native child dies while its genuine `turn/start` ACK is withheld, and Host persists `execution-unknown` with one lease revocation; retry/duplicate may not replay the prompt. A fresh independent Host and adapter must reopen the same journal/profile and still refuse the input without launching another child. The loopback upstream must bind an OS-assigned port, count actual requests (including a possible request before the held ACK), and close its sockets; a held ACK alone does not imply no Model effect. Transport and Host own distinct facts: transport owns PID/exit/pending RPC; adapter owns the old lease; Host owns journal admission and persisted uncertainty. No stale old-turn frame may advance a newer run. Host selection is immutable for this session: attempts to switch user Model by passing a different spec must refuse before issue/spawn, rather than pretending two separately created sessions prove switching. Fragmented unterminated stdout or aggregate early events exceeding the byte bound produce the same unknown receipt and owned-child cleanup. The opt-in actual-child byte-fault Host join reuses a genuine pinned native `turn/start` ACK (held by the test proxy), injects _test-origin_ stdout faults (not native-origin frames), and verifies OS reaping, persisted unknown on independent reopen, one lease revocation, no replacement process/request and bounded fake-upstream count. Codex may handle SIGTERM and exit 0; OS reaping is established by its real `exit` event and non-null `exitCode` or `signalCode`, not by requiring a SIGKILL status. For stale turn isolation, a bounded test stdout proxy captures verbatim pinned CLI item/text/tool/usage and completion frames and injects them into the next child's stream **before** releasing its genuine `turn/start` ACK: the old turn cannot project, settle the new send or revoke the new lease. Only a matching genuine native completion may settle the new turn. Desktop continuous and mobile replayable views remain projections of the Host journal, not adapter-owned copies.
