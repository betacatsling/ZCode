# Model Gateway: Codex Responses first slice

Status: implementation contract for Gateway slice **0.2.0**. This is an isolated P5 slice. It does not certify P5, a real Provider route, model quality, or production admission.

## Goal and ownership

Provide one target-local Model Gateway that accepts only the observed Codex Responses streaming ingress subset and calls a pre-bound `@zcode/contracts` `Model`. The caller/composition layer remains the sole owner of `BindingPlan` resolution and calls the existing `bindHostModel`; this module receives that bound `Model` as an injected port. Each returned grant exposes the immutable Host session, catalog fingerprint, and actual Provider/model identity bound to that Model. The Gateway does not import CLI bootstrap, create a second Provider client, execute tools, or become a production default.

The Gateway owns only issued grants, their expiry/revocation, request/output budgets, active request cancellation, bounded Host turn leases, and global concurrency. Each grant is immutable and binds one target, one host session, `openai-responses`, one model-binding fingerprint, one public model alias, and one bound `Model`. Same-binding renewal extends that grant without changing its Model or token scope. A turn lease can extend authorization only for the grant's frozen binding while the Host owns the matching active turn; it is explicitly renewed by the target Host and ends on the matching terminal event. A changed binding requires revoking the old grant and issuing a new token. The bearer token is random, short-lived, sent once to the harness, indexed by a digest, and never logged. Each host session receives its own grant. A request cannot select a different model or Provider URL.

```text
Host send: current catalog snapshot -> BindingPlan -> bindHostModel -> turn admission fact
                                                               -> immutable session grant / turn lease
                                            |
Codex app-server -> loopback HTTP -> Responses decoder -> grant + budget admission
                                            -> bound Model.streamText(AbortSignal)
                                            -> Responses SSE encoder -> Codex
Codex tool execution stays in Codex; function_call_output returns in the next request.
```

## Network and lifecycle rules

- Bind only `127.0.0.1` or `::1`; tests use an ephemeral loopback port. No remote listener or SSH path is part of this slice.
- Accept only `POST /v1/responses` with `stream: true`. Unknown paths, methods, and auxiliary endpoints return a structured 404/405; no model call occurs.
- Require the grant bearer token. Reject missing, unknown, revoked, or wrong-protocol grants before reading/decoding a body or calling the model. An expired base grant remains authorized only while its matching Host-turn lease is active; if both windows expire, reject before Model execution. Revocation aborts all active requests for that grant.
- A Host may renew a grant only by grant ID plus the expected immutable binding fingerprint; renewal cannot replace its Model, alias, session, or route. It rotates no token and cannot revive a revoked grant. The Host may begin one turn lease on an idle grant, renew that lease only for the same Host turn, and end it only for the matching turn. Lease extension is bounded by the configured short lease duration. Expired tokens remain unusable when no matching active lease exists; a new Model binding always gets a new token.
- Bound body bytes, requests per grant, total and per-request output-token reservations, per-grant concurrency, and process-wide concurrency. Oversized, exhausted, or overloaded requests fail before model execution.
- A client disconnect or cancellation aborts the `Model.streamText` signal. A request that exits without a finish event consumes its output reservation; a finished request settles the reservation to reported output usage, preventing unlimited retries by cancelling early.
- `Model` generates only. The Gateway never runs a tool or retries a generation. Duplicate model requests therefore cannot create duplicate tool side effects in this module.

## Supported Responses subset

The allowlist is pinned to fields observed from the isolated Codex CLI 0.157.1 trace and fields needed for the Responses input/output contract. That trace sent `POST /v1/responses` with `client_metadata`, `include`, `input`, `instructions`, `model`, `parallel_tool_calls`, `prompt_cache_key`, `reasoning`, `store`, `stream`, `tool_choice`, and `tools`. It used `stream: true`, `store: false`, `tool_choice: "auto"`, `parallel_tool_calls: true`, `reasoning.effort: "none"`, and `include: ["reasoning.encrypted_content"]`. The decoder rejects unknown fields and unsupported values before model execution.

- Input is text only: top-level `instructions` and message items with `system`, `developer`, `user`, or `assistant` role; message content is a string or `input_text` / `output_text` parts. Codex message `id` values are accepted and discarded because the Model transcript has no item-ID field; function correlation continues to use `call_id`. Top-level `instructions` and leading `system` input messages map to `ModelRequest.systemInstructions`; input `developer` messages remain `ModelInputMessage` entries with `role: "developer"`. System-role input after conversation content is rejected because moving it to the high-priority instruction field would reorder the request. The CLI Model adapter sends `systemInstructions` using the OpenAI Responses `instructions` option and sends developer messages as actual `developer` input items. The Codex factory admits only `openai-responses` model bindings with reasoning disabled; providers that cannot express both layers are unsupported.
- `client_metadata` accepts only the observed Codex 0.157.1 keys with bounded string values and requires `session_id` plus `thread_id`. On first use the grant binds those two values; later requests with the same token must match both. Other metadata values are limited to 512 characters; observed `x-codex-turn-metadata` is limited to 16 KiB. `prompt_cache_key` is accepted as a bounded string because Codex 0.157.1 sends it on every observed request, but the Gateway does not forward it or claim prompt-cache support; it remains an explicitly unsupported optimization hint, not model input.
- Assistant history supports visible text and Responses `function_call` items. Adjacent function calls form one assistant tool-call batch, preserving call order and any surrounding assistant text; an intervening input item ends that batch, so calls from separate turns cannot merge. Each `function_call_output` must match exactly one earlier call by `call_id`; message/item `id` values are accepted and discarded, while missing, duplicate, orphaned, or unsupported call/result shapes fail closed. Outputs become ordered `tool` messages with `toolCallId` and their paired function names. The Gateway does not invoke the tool.
- Tools support the standard Responses function shape only, mapped to `ModelToolContract`. Codex's `web_search` and `multi_agent_v1` built-ins are disabled in the probe using its isolated configuration; if such non-function tools arrive, the Gateway rejects the request. Other tool variants, unsupported tool-choice modes, and unsupported schema envelope fields are rejected. A custom tool schema remains JSON Schema data and is not interpreted by the Gateway.
- Only the text generation controls certified by the bound Model port are mapped. The requested model must exactly equal the grant's public alias. The Gateway never uses request content to derive a Provider, model ID, URL, or credential.
- Only `parallel_tool_calls: true` is admitted. The shared Model request has no control that can guarantee a single call when parallel calls are disabled, so `false` is rejected by the decoder before `Model.streamText` or any function-call item can be emitted; the encoder retains its multiple-call guard as defense in depth.
- Reasoning is accepted only for `effort: "none"`. `include: ["reasoning.encrypted_content"]` is accepted only on this no-reasoning path; it means there is no private state to return. If the bound model emits any reasoning event, the Gateway aborts and returns an explicit unsupported-feature error. It never fabricates encrypted content or signatures.
- Images, files, audio/video, structured output, built-in tools, background/conversation state, prompt templates, actual prompt-cache behavior, cache controls other than the inert prompt_cache_key hint, arbitrary provider extensions, and non-streaming responses are outside this slice and are rejected when present with a value that requests the capability.
- Output is a Responses SSE stream with a monotonically increasing `sequence_number` on each event, complete message/content-part and function-call item lifecycles, and a terminal `response.completed`, `response.incomplete`, or structured `error`. Function-call argument deltas are accumulated and validated as JSON before the item is completed. `length` maps to `response.incomplete` with `status: "incomplete"` and `incomplete_details.reason: "max_output_tokens"`; other finish reasons outside `stop`, `length`, and `tool-calls` fail explicitly. Usage is a replacement snapshot in the terminal Response, not a delta to add to prior responses.

## Acceptance evidence

Pure decoder/encoder tests cover instruction layers, visible assistant text with adjacent function-call batches, tool pairing, multiple tool argument streams, usage replacement, finish reasons, and each unsupported shape. An isolated AI SDK Responses provider test inspects the actual serialized loopback request body. HTTP tests exercise authentication isolation, immutable grant model identity, same-binding renewal, expired-token rejection, Host-turn lease renewal/end, revoked-token rejection after route replacement, body/request/output budgets, concurrency, disconnect abort, unknown routes, and no model execution on rejected input.

The completed isolated real Codex app-server probe uses CLI 0.157.1, Gateway 0.1.0, temporary `HOME`, a mode-0700 `CODEX_HOME`, a temporary workspace, and a fake token. Its only model endpoint is the loopback Gateway. It disables optional `web_search` and `multi_agent` tools so the request's tools remain in the supported function subset. It exercised initialize/thread/start/turn/start, generated text, a tool call/result roundtrip that wrote only `gateway-roundtrip.txt` in the temporary workspace, and `turn/interrupt` with both `threadId` and `turnId`. `workspace-write` could not launch in this container because Codex 0.157.1 rejected the app-server socket directory mode; this isolated fake-only probe therefore used `danger-full-access`, while its fixed tool command and working directory remained confined to the temporary workspace. The trace records paths and field names/shapes without prompt, token, or credential values. A successful Fake Model run certifies only the recorded local control/model protocol combination.

The 0.2.0 host integration exercises per-turn binding with CLI 0.157.1 and a loopback Fake Model: an active turn keeps its original model after a catalog update; an idle turn rebind rotates the token, resumes the same opaque thread, preserves context, and uses the next catalog Model; an expired same-binding grant renews under an injected clock; and a long fixed tool can cross the old short TTL while the target Host renews its Host-turn lease with no GUI attached. These local checks do not certify a live Provider or production sandbox.

At task start, `/home/ykzheng/.local/bin/codex --version` reported `codex-cli 0.157.1`. The installed standalone releases contain 0.153.4, 0.154.0, and 0.157.1; 0.156.1 is not available here. The 0.157.1 run is a separate validation row from the historical 0.156.1 observation in `CODEX-APP-SERVER.md`; it does not rewrite the old observation as if it used 0.157.1.

## Protocol references and source provenance

The implementation follows the official [Responses create reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) for input, instructions, streaming, tools, include, and usage fields; the [Responses streaming guide](https://developers.openai.com/api/docs/guides/streaming-responses) and [function calling guide](https://developers.openai.com/api/docs/guides/function-calling) for typed SSE events and tool argument deltas; and [Codex config basics](https://learn.chatgpt.com/docs/config-file/config-basic) for disabling optional web search and multi-agent features in the isolated probe. The repository's `CODEX-APP-SERVER.md`, `probeCodexAppServer.mjs`, and `probeCodexModelGateway.mjs` are local protocol evidence. No third-party implementation source is copied; the Gateway is a local implementation of this bounded contract.

The checked-in Codex app-server contract is generated by `codex app-server generate-json-schema` from CLI 0.157.1; its versioned schema artifact is a protocol lock, not a claim that a later CLI has the same contract. See `CODEX-HARNESS-ADAPTER.md` for the adapter lifecycle, version gate, and experimental admission boundary.
