# Claude Code structured control and Messages ingress

Pin observed CLI 2.1.263 for first fixtures. Use the supported Agent SDK/structured stream, not TUI parsing; set a target-local isolated `CLAUDE_CONFIG_DIR`, disable implicit project/global plugins and MCP sources until their permissions are verified, and preserve native session IDs for resume. Never mutate the user's personal `~/.claude` or forward its subscription credentials as a generic Provider key. `canUseTool` is not a universal authorization gate: auto-allow rules can bypass it. A `PreToolUse` hook or an equivalent verified backend control point must deny or pause *before* write/bash execution; stale decisions bind the original tool/turn/epoch only.

Model ingress is Anthropic Messages `POST /v1/messages` (optional count_tokens and models routes by observed version). A loopback Gateway accepts only a session-bound token and pinned model binding. It maps supported fields to the existing ZCode Model executor, and must reject unsupported `anthropic-beta`, opaque thinking/signatures, cache/routing behaviors, images, tool variants and new feature fields rather than silently stripping them. Successful control-plane stream with a fake model proves neither real Provider routing nor the required multi-turn task quality.
