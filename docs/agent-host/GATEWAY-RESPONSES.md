# Responses codec (foundation; Codex CLI 0.156.1)

Owner: `packages/services/src/model-gateway/ingress/responses.ts` validates the request and maps only representable content into `@zcode/contracts` `ModelRequest`; `egress/responses.ts` owns one response stream's output item identities and terminal state. The gateway core owns auth, alias validation, abort signal attachment, SSE serialization, backpressure and budgets. No independent model client or CLI config changes here.

```text
CLI POST /v1/responses -> decoder (reject before executor) -> gateway binding -> Model.streamText
                                                          -> encoder -> SSE frames -> CLI
```

Only `stream:true`, plain text messages (including string input and assistant `output_text`), ordered system instructions (including `instructions` preceding input), named function declarations, paired function_call/function_call_output, `max_output_tokens`, `tool_choice:auto`, `parallel_tool_calls:true`, `store:false`, `reasoning.effort:none`, optional `include:["reasoning.encrypted_content"]` with reasoning disabled are supported. `client_metadata` is opaque, nonsemantic diagnostics ignored and never logged; `prompt_cache_key` is an advisory OpenAI Responses cache affinity key: validate non-empty bounded string and pass as typed `ModelRequest.promptCacheKey` to the existing OpenAI Responses SDK; unsupported provider routes reject before dispatch. It is not Anthropic cacheControl and does not promise a cache hit. Message IDs are transport-only. `instructions` and system input retain order; developer is preserved as a native `ModelInputMessage.role:'developer'` (never promoted to system). The joined Model runtime commit `0d268dd` gates it to its exact supported OpenAI Responses fetch path and rejects unsupported Provider APIs before outbound execution. Other request semantics such as `prompt_cache_key` must still pass separate validation before admission. Namespace, web_search, image/audio, opaque reasoning, provider cache, sampling/unknown parameters and non-auto tool choice reject before model execution. No encrypted reasoning signature or cost is synthesized. Plain reasoning and optional opaque encrypted reasoning are distinct capabilities: a Model reasoning event can be emitted live as a Responses reasoning item/summary without claiming encrypted content; if providerMetadata.openai has an original nonempty `reasoningEncryptedContent` and exact original `itemId`, emit those opaque values unmodified. Input history reasoning must have original encrypted_content with a matching item id to replay statelessly through the existing OpenAI Responses SDK; reject plaintext-only reasoning history because the SDK drops it. Never manufacture encrypted output from plain text. AI SDK inputTokens includes cached tokens; Responses usage cached_tokens is a subset of input_tokens, not an increment. Gateway binding separately validates model alias.

Input function calls must have unique call_id, valid complete JSON object arguments, and every output pairs a preceding call; duplicate/unpaired outputs reject. The decoder never executes tools. `finish` usage is a replacement snapshot, not accumulated estimates. Output text blocks and function items use deterministic IDs scoped to request ID and output index. Deltas are followed by a full final snapshot that **replaces**, not appends to, earlier text; no duplicated output item. Incomplete/malformed JSON, stream error, missing finish, unsupported reasoning, or abort emits `response.failed` (never `completed`). Terminal event occurs once. No upstream exception text is exposed.
