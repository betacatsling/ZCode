# Responses codec (foundation; Codex CLI 0.156.1)

Owner: `packages/services/src/model-gateway/ingress/responses.ts` validates the request and maps only representable content into `@zcode/contracts` `ModelRequest`; `egress/responses.ts` owns one response stream's output item identities and terminal state. The gateway core owns auth, alias validation, abort signal attachment, SSE serialization, backpressure and budgets. No independent model client or CLI config changes here.

```text
CLI POST /v1/responses -> decoder (reject before executor) -> gateway binding -> Model.streamText
                                                          -> encoder -> SSE frames -> CLI
```

Only `stream:true`, plain text messages (including string input and assistant `output_text`), ordered system instructions (including `instructions` preceding input), named function declarations, paired function_call/function_call_output, `max_output_tokens`, `tool_choice:auto`, `parallel_tool_calls:true`, `store:false`, `reasoning.effort:none`, optional `include:["reasoning.encrypted_content"]` with reasoning disabled are supported. `client_metadata` is opaque, nonsemantic diagnostics ignored and never logged; `prompt_cache_key` is an advisory OpenAI Responses cache affinity key: validate non-empty bounded string and pass as typed `ModelRequest.promptCacheKey` to the existing OpenAI Responses SDK; unsupported provider routes reject before dispatch. It is not Anthropic cacheControl and does not promise a cache hit. Message IDs are transport-only. `instructions` and system input retain order; developer is preserved as a native `ModelInputMessage.role:'developer'` (never promoted to system). The joined Model runtime commit `0d268dd` gates it to its exact supported OpenAI Responses fetch path and rejects unsupported Provider APIs before outbound execution. The Gateway's independent strict ModelRequest schema must also accept that validated bounded `promptCacheKey`; otherwise the real CLI repeatedly receives `invalid_model_request` before Model invocation even though the Responses decoder accepted its wire request. Unknown runtime fields remain rejected. Namespace, web_search, image/audio, opaque reasoning, provider cache, sampling/unknown parameters and non-auto tool choice reject before model execution. No encrypted reasoning signature or cost is synthesized. Plain reasoning and optional opaque encrypted reasoning are distinct capabilities: a Model reasoning event can be emitted live as a Responses reasoning item/summary without claiming encrypted content; if providerMetadata.openai has an original nonempty `reasoningEncryptedContent` and exact original `itemId`, emit those opaque values unmodified. Input history reasoning is **not admitted** in the current off-only Codex profile, including a syntactically valid original `id` + `encrypted_content` + `summary`. `decodeResponsesRequest` throws `ResponsesCodecError("unsupported_reasoning_replay", 422, "input[N]")` before Model execution. The typed Model content block can carry opaque options, but this ingress cannot prove that the frozen effective selection resolves to the *same original provider route*; passing it to a changed route, or through a stateless serializer that strips it, silently changes the private state. Do not downgrade reasoning to text or manufacture a signature. `include:["reasoning.encrypted_content"]` with `effort:none` alone is still permitted and does not imply private-history replay. Plaintext-only/malformed reasoning is rejected as `unsupported_reasoning`. Output may emit only provider-supplied original opaque metadata, never generated opaque state. Capability can widen only after route-binding and full two-request fake-upstream proof. Existing developer-role and cache-key handling are independent.

```text
CLI request → Responses decoder (only owner of wire private-state admission)
  → [reasoning history?] reject 422 before Gateway Model.streamText
  → [ordinary off-only text/tool input] Gateway's bound Model → provider
Gateway response → encoder emits original opaque metadata only when supplied by Model
```

No private state is persisted by Gateway; the Host retains turn/epoch and token budget. Repeated requests with private history reject identically; no retry, provider fallback or route switching. Desktop continuous versus mobile replayable delivery stays with Host. Tests must obtain a genuine-shaped reasoning item from the encoder then replay it alongside a second-turn prompt, assert 422 and zero Model calls, including a changed bound route and malformed history; ordinary developer role/cache-key request must continue to execute. Never manufacture encrypted output from plain text. AI SDK inputTokens includes cached tokens; Responses usage cached_tokens is a subset of input_tokens, not an increment. Gateway binding separately validates model alias.

Input function calls must have unique call_id, valid complete JSON object arguments, and every output pairs a preceding call; duplicate/unpaired outputs reject. The decoder never executes tools. `finish` usage is a replacement snapshot, not accumulated estimates. Output text blocks and function items use deterministic IDs scoped to request ID and output index. Deltas are followed by a full final snapshot that **replaces**, not appends to, earlier text; no duplicated output item. Incomplete/malformed JSON, stream error, missing finish, unsupported reasoning, or abort emits `response.failed` (never `completed`). Terminal event occurs once. No upstream exception text is exposed.

The CLI's native model alias is wire-only; it does not select or override the frozen gateway provider/model. The real installed CLI must pass a scoped, bounded Gateway token through an actual two-request tool/result continuation to the existing Model adapter against an isolated fake Responses upstream before this seam is accepted. Unknown request fields/endpoints reject with a reason; no silent drops of semantic fields. The fake upstream is not real-provider or restart/resume certification. In the isolated native test a read-only sandbox plus declined native escalation prevents the attempted write; a subsequent native turn is interrupted while an upstream response is pending, and revocation/interrupt must not emit a completed response.
