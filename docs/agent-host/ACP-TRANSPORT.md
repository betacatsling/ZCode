# ACP v1 raw stdio transport seam

Source: full ZCode v0.3 plan §3.1, §P6, §12.3; frozen foundation contract (2026-09-24). Protocol evidence: `@agentclientprotocol/sdk@1.5.0` published schema `dist/schema/index.js` declares `PROTOCOL_VERSION = 1`, method names `initialize`, `session/new`, `session/load`, `session/prompt`, `session/cancel`, `session/update`, `session/request_permission`, `fs/*`, `terminal/*`; `dist/schema/types.gen.d.ts` documents version negotiation, `agentCapabilities.loadSession`, request/response shapes. Official overview and session setup: https://agentclientprotocol.com/protocol/v1/overview and https://agentclientprotocol.com/protocol/v1/session-setup . No SDK dependency is introduced: this is an independently implemented bounded v1 subset.

## Behavior and owner

A descriptor names an exact executable, argv, isolated cwd/profile environment and expected executable version; probe exact version before launch. A caller can inject a process/stream factory for tests and target-specific execution. This transport alone owns pending RPC IDs, incoming permission gates and active native session ID. It never owns host IDs, model selection, persistence, agent tools or V4 events. No process starts on import/discovery. ACP is NOT model injection; model binding remains independent. Capability `loadSession === true` gates load; absent load means history-only, not resume. Unknown session updates are safe observational data, never executable commands. Unknown requests receive method-not-found; filesystem/terminal/MCP client operations default-deny. Callback injection and capability advertisement are currently rejected because request correlation and cancellation fencing are not proven. The agent executes its own tools; this client does not rerun them.

```text
caller -> transport (one pending RPC ID) -> ACP agent
agent session/update -> validated session ID -> observational listener
agent permission request -> held RPC ID -> caller decision -> one response
cancel -> invalidate permissions + notify agent -> await original terminal prompt reply -> poison connection
close/exit -> reject pending calls -> ignore late replies
```

Initialize must answer integer protocol version 1 exactly; unknown version closes transport. `session/new` sends absolute cwd and `mcpServers: []`; `session/load` requires advertised capability and opaque native ID. Prompt requires an established session and text blocks; one outstanding prompt per transport. Notification updates contain session ID and structured update; malformed JSON, invalid envelopes, oversized frames, duplicate inbound request IDs and child exit fail closed. Unknown update extensions stay observational and never gain authority. Request IDs are process-local, no replay or idempotent retry of a dispatched prompt. Cancel has ACP session scope; one active prompt per transport prevents accidental cross-turn cancellation. A late approval is rejected after cancel/close. Close ends streams/process and rejects unresolved requests without fabricating a successful turn. Stderr is drained but never logged verbatim.

## Acceptance and migration boundary

Two different descriptor-driven fake agents: load-capable vs history-only, version rejection, structured updates and unknown extensions, pending permission and cancellation/late decision, duplicate/malformed frames, child exit/cleanup, default deny for FS/terminal and injected authorization. No canonical AgentHost/shared/UI/manifest registration change in this seam. Real executable certification, model binding, target lifecycle/detach, and durable approval admission are later integration gates. Only an already-durable authorized approval should be supplied to `resolvePermission` by its future host caller; this seam cannot prove host durability. Desktop and mobile delivery/replay both remain with later Host owners.

Factory inputs for later manifest/Host integration: executable absolute path, argv array, absolute target-local cwd, complete isolated environment (HOME/profile, no inherited credentials), exact version probe `{argv, exact}`, target-specific launch/probe injection; `createAcpTransport(descriptor, options)` returns a raw connection. Inspect `capabilities.loadSession` after initialize; expose only supported operations and keep `sessionId` opaque. Pass only the durable interaction gate from the Host; client filesystem/terminal callbacks remain disabled. Never advertise host-managed model support from this result.

Candidate for _later_ real certification: public `@zed-industries/claude-code-acp@0.16.2` (npm tarball package.json bin `claude-code-acp`, README documents ACP stdio agent, permission requests, MCP, terminal; package depends on `@agentclientprotocol/sdk@0.14.1`). Pin its executable/package and independently verify an exact version probe that works for its CLI before configuring this transport. No global installation, account use, live ACP execution, model-route or session/load certification was performed here. The candidate is Claude-backed; it is **not** evidence of arbitrary model injection. Independently certify a second long-tail agent and capabilities at integration time.

Cancellation clarification: `session/cancel` is a notification, not a prompt completion. An original prompt response with explicit cancelled stop reason is required; JSON-RPC error or invalid/unknown stop is execution-unknown. A cancelled connection is not reused for another prompt: updates identify only native session, not prompt. Optional client FS/terminal callbacks are rejected at connect until they can be fenced across asynchronous cancellation and native session identity.
