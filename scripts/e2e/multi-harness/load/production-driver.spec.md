# Production driver contract (load lane)

Runner creates fresh disposable Git fixture, isolated HOME/XDG/Desktop userData/Web profile; driver verifies canonical descendants before loading product modules. It never reads account configuration, opens a Provider socket or starts SSH/CLI. Target owns Git discovery and lifecycle; Catalog owns adopted workspace references; durable Host owns accepted commands/events; only browser owns paint and draft. Driver owns scheduling/cursors/metrics, never copies owner state as an alternate authority.

Order: target read-only discover -> adopt five workspace candidates -> Host create ten trusted synthetic sessions -> mount real Shell/Sidebar/Pane with same Catalog/Host -> inspect actual DOM + reopen journal -> emit unique source events -> await committed sequence -> desktop continuous subscription or web query/snapshot/gap repair -> painted input/switch -> detach UI only -> query replay by cursor -> close browser then Host/Target/Catalog, wait for owned children, sample host memory. Any missing component, stale scope, gap, missing process metric, inaccessible journal or unproven identity fails before `mountedSurfaces` is reported. Runtime-unknown never treated as idle. Reconnect never resends a prompt. No timeout substitutes for sequence completion.

Acceptance: 50 real worktrees (including main), ten sessions over five expanded workspaces, 100k committed events, eight hours monotonic, two distinct delivery runs; >=20 samples/session, separate measured host/renderer memory and owned child process counts before and after cleanup, no implicit CLI launch, read-only discovery. No synthetic fixed latency or fake UI fixture is valid. A smoke does not certify production. Baseline must be preserved on same hardware/config at a different commit; compare both typed and switch p95, retain raw results. Driver may fail closed until whole-shell external owner attachment and process metrics are available from committed source.
