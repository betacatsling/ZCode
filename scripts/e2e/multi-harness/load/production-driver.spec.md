# Load runner and production-driver contract

## Ownership and event order

The runner owns the disposable Git fixture, schedule, result artifact, provenance snapshots, baseline comparison, and cleanup registry. The CLI owns only argument parsing and process-exit reporting; its exit code is derived from the same persisted run status. The driver owns the synthetic backend composition and a deterministic, bounded autonomous source workload. `AgentHostTargetService` remains the sole owner of accepted commands, event sequencing, and durable journal writes; this load source does not claim accepted prompts, dispatch a user `send`, call a Provider, launch SSH/CLI, or write workspace files. Target owns Git discovery/lifecycle, Catalog owns adopted workspace references, and Host owns session/event state. Browser owns paint and drafts; the runner/driver cannot substitute synthetic values for browser evidence.

Sequence: create isolated external fixture and HOME/XDG/Desktop/Web profiles -> Target read-only discovery -> Catalog adopts real candidates -> Host creates ten synthetic sessions -> autonomous source emits canonical `turn.started`, non-empty `text.delta`/`message.finished`, and bounded `tool.started`/`tool.finished` lifecycles through the trusted adapter subscription -> await Host journal commit and query the owner snapshot -> mount the real Shell/Sidebar/Pane with the same Catalog/Host -> inspect actual DOM, renderer consumption, and reopened journal -> desktop continuous subscription or web query/snapshot/gap repair -> measured painted input/switch -> detach UI only -> query replay by cursor -> close browser then Host/Target/Catalog, reap registered children, sample separate host/renderer process memory. No timeout substitutes for sequence completion. Synthetic lifecycle emissions are explicitly autonomous and never counted as accepted prompts; the Host journal sequence is the source of committed-event counts.

## Provenance and outcomes

Each artifact has a schema version, actual Node/V8/platform/architecture identity, and hashes for the actual driver entrypoint and selected build artifact. Synthetic backend emits one canonical owner-committed event per scheduled emission in a seven-step turn (start, nonempty delta, tool start, tool finish, nonempty delta, message finish, turn finish); it never calls send. The first ten scheduled events start ten distinct sessions. Owner activity must report ten running synthetic turns before claiming ten active sessions; this is *not* evidence of ten accepted user prompts. Later emissions continue bounded turns without padding with extension events. The runner snapshots the selected Git checkout (HEAD plus clean tracked/untracked status), loaded driver/support source files, build artifact, build-preparation manifest, and runtime identity before measurement and verifies those exact inputs again before writing the result. The production driver commit is independently checked against the selected checkout, not accepted from a self-report alone. For a non-contract-stub production driver, the actual loaded `.mjs` entrypoint must live within that selected checkout and be hashed before import and after measurement; CLI runner/facts/measurement source inputs are also snapshotted before driver import and rechecked after measurement; the checkout must have neither tracked edits nor untracked files. An external contract stub is only test evidence, never a mounted product driver. A comparator rejects missing/unknown schema or runtime/driver/source/build mismatches, same-commit baselines, changed/tampered source or artifact hashes, invalid sample population, and invalid preparation provenance. A build-success manifest proves only its declared source/artifact preparation; it does not prove the binary was mounted or rendered.

A CLI-loaded `contract-stub` benchmark is always `contract-stub-only` (exit 2), even if its arithmetic comparison is within budget; stub p95 values are never product paint evidence. `smoke-only` means a completed smoke, not a production pass. `latency-measured` is reserved for a comparable controlled benchmark within both <=1.10 p95 budgets. Failed work is `failed` (CLI exit 1); pending, unsupported, missing, or incomparable comparisons are explicit non-pass outcomes (CLI exit 2); only a completed smoke or valid within-budget controlled comparison may exit 0. Acceptance cannot silently pass while its comparison is pending. When `--baseline` is supplied, unreadable/forged/non-comparable baseline inputs must be reflected in the persisted status and nonzero CLI exit.

## Acceptance boundary

Acceptance remains 50 real worktrees (including main), ten sessions over five expanded workspaces, 100,000 committed Host events, eight hours monotonic, and separate desktop-continuous/web-remote-replayable runs. Require >=20 input and switch samples per session, separate actual host/renderer memory and owned child counts before/after cleanup, no implicit CLI launch, and read-only discovery. A smoke does not certify production. A comparable baseline must be preserved on the same hardware/config at a different commit; retain raw results and compare typed and switch p95 independently. Driver must fail closed until whole-Shell external owner attachment, actual browser paint/renderer consumption, and separate process metrics are available. No synthetic latency, renderer/cursor/CPU metrics, fake UI fixture, or successful build is evidence of a mount. Top-level `dispose()` is idempotent and works on partial open; `open` registers cleanup before async owner startup. Runner passes delivery explicitly, never inferred from argv, and driver rejects a mismatched source checkout. This backend's synthetic lifecycle is meaningful Host workload only; it does not establish product/UI acceptance.
