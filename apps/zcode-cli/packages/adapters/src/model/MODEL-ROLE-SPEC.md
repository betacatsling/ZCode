# Model developer-role routing (OpenAI Responses only)

## Clean-install test dependency contract

The adapters package owns its test-only `ajv` import directly as a dev dependency, pinned to the existing lockfile Ajv 8.18.0 snapshot. The `openai-developer-role.test.ts` schema assertion remains included in adapters `tsc` build and focused test execution; neither a parent workspace `node_modules` nor a transitive dependency is a valid source for this import. A frozen, scripts-disabled workspace install must build `@zcode/adapters...` and run the focused fake-endpoint role/schema regression without a real provider. The package manifest and its pnpm importer are the only dependency write path; there is no runtime behavior, protocol, state owner, or migration change. If the direct dependency cannot resolve under a clean frozen install, the prerequisite fails instead of suppressing the test.

The existing public `ModelRequest.messages` retains the source message order and text. `developer` is an additional `ModelMessageRole` and its JSON schema is strict; it is not an alias of `ModelTextRequest`. Native requests without developer preserve the existing SDK path and options exactly. Model owns pre-dispatch admission; each SDK attempt owns its immutable instruction plan and its own provider fetch. No global role map, prompt markers, duplicate client or credentials.

For requests with developer, only the bound `openai-responses` API may run. The AI SDK has no per-message developer role; force its per-request `openai.systemMessageMode=system`, then at the existing OpenAI Responses provider fetch boundary require JSON text with an `input` array and verify the **entire ordered list** of system/developer instructions (count, text, SDK-produced system role and exact supported body shape) against the original messages. Change only each intended developer item's `role`; forward the otherwise identical body, headers, abort signal and URL to the existing option-map, business-error, proxy/auth and response wrappers. If the SDK changes instruction structure, body format or sequence, reject before any network request. The SDK `openai.instructions` side field must not be used for extended requests. Any caller-provided `openai.systemMessageMode` other than `system` is rejected rather than silently overridden.

Anthropic Messages and OpenAI-compatible Chat Completions have no certified developer-route implementation. Reject developer requests before dispatch with stable `InvalidModelRequest` and `retryable=false`; do not merge into system or user. Model Request admission must retain raw message roles for history/retries. The OpenAI Responses role adapter must not alter native requests with no developer message. Asynchronous order: Model validation → per-attempt immutable plan → SDK converts → fetch verifies/restores → existing transport → normalized response. Reattempt constructs the same source plan; stale plans never share a fetch closure.

Acceptance: strict JSON schema accepts developer and rejects unknown roles; mixed ordered system/developer across concurrent calls and retries reaches fake HTTP unchanged except intended roles; SDK body count/text/shape drift refuses before HTTP; ordinary native payload unchanged; unsupported providers refuse before HTTP; cancellation and usage/metadata remain normal AI SDK behavior. Fake endpoint tests do not certify live model/permission behavior.

## Prompt-cache affinity

`ModelRequest.promptCacheKey?: string` is a per-request, non-secret advisory OpenAI Responses cache key. Only a non-empty string with bounded length is accepted, with the same bytes sent through the pinned SDK `openai.promptCacheKey` option; no cache result or cost saving is promised. Reject it before network on Anthropic or OpenAI-compatible routes (no verified equivalent). A caller's existing provider `openai.promptCacheKey` must not conflict with this typed key: if both are set to different values, reject rather than overwrite. Do not alter requests without the typed key. Response usage remains SDK-derived, not inferred from the key. Test exact fake HTTP `prompt_cache_key`, mismatch/non-supported denial and ordinary request preservation.
